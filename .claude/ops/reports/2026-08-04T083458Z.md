## Blocking tooling gap (read this first)

`scripts/adr_checkpoint.py classify .claude/docs/adr` scanned **0 ADRs** against the corpus.
Root cause: the script's directory-mode (`scan_dir`) only recognizes YAML frontmatter
(`doc-type: adr` / `id:` / `status:` / `supersedes:`) at the top of each file. This repo's real
ADR shape is a directory of one-file-per-ADR `*.md` files, each with an `# ADR-NNNN — Title` H1
heading and a markdown `| Field | Value |` table (Status/Date/Proposed by/Ratified
by/Repairs/Supersedes-Superseded-by) — no frontmatter at all, and not the single-monolithic-file
`## ADR-NNN` shape either. Neither of the two shapes the script supports matches this repo's
convention. `scripts/adr_ratify.py` (this repo's own ADR-0149 ratification script) already parses
this exact table format directly, confirming it's the repo's real, intentional convention — not
a fluke.

silently, unless this is fixed. I did not run `advance` (would write a checkpoint recording
0 known ADRs — worse than no checkpoint, since it would look like a clean baseline was
