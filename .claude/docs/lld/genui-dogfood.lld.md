## 2. LLD-C1 — the asset pair

- **Generation script** `scripts/build-dogfood-assets.mjs`: shells ONE real Vite (Rolldown) build
  with a dedicated inline config — entry = a tiny in-script virtual entry importing
  `@agent-ui/components/foundation-styles.css`, `@agent-ui/components/component-styles.css`,
  `@agent-ui/components/components`, `@agent-ui/icons/phosphor` (the `_page.ts` cascade members
  [1][2][3][3b], verbatim, in that order) — `build.lib` IIFE format, minified, `cssCodeSplit:false`,
  into a scratch outDir (the `build-css.ts` scratch discipline: never the real `dist/`). Emits the
  committed module from the two build artifacts:

  ```ts
  // dogfood-assets.ts — GENERATED by scripts/build-dogfood-assets.mjs — DO NOT EDIT.
  // <build date · source of each string · measured sizes>
  export const DOGFOOD_CSS: string = /* the joined, flattened CSS text */
  export const DOGFOOD_JS: string = /* the single-file IIFE bundle text */
  export const DOGFOOD_TAGS: readonly string[] = [/* every ui-* tag the bundle self-defines */]
  ```

  `DOGFOOD_TAGS` is derived IN the script by scanning for `.define("ui-` / `.define('ui-` call
  sites — deliberately NOT the full `customElements.define(` literal, which a minifier may alias
  away (`const c=customElements;c.define("ui-…")`); if even the method-call form proves unstable
  under minification, the script scans the PRE-minify intermediate instead (recorded fallback).
  The fleet defines statically, one guarded define per control, so the scan is grep-derivable and
  the LLD-C5 set-equality gate compares committed data, not a runtime bundle execution.
- **Subpath export**: `"./dogfood-frame": "./src/controls/sandbox-frame/dogfood/dogfood-assets.ts"`
  — opt-in only; a trip-wire line in the existing barrel-budget gates asserts neither default barrel
  reaches it (the ADR-0137 zero-bytes gate pattern).
- **Freshness gate** (`dogfood-assets-freshness.test.ts`, Node project): re-runs the generation
  into scratch and compares byte-for-byte against the committed module (the theme-provider LLD-C11
  shape). Uses `build-css.ts`'s single-flight/lock discipline if a second build-shelling test ever
  lands in the same run. **Purity gate** in the same file: the committed CSS/JS match no
  `url(` / `@import` / `import(` pattern that resolves outside `data:` (SPEC-R12's closed-network
  proof).
- **Determinism**: minified IIFE output for a fixed source tree is deterministic under Rolldown; the
  gate's rebuild-and-compare IS the proof — if an environment delta ever breaks byte-determinism the
  gate reds and the comparison relaxes to structural (recorded fallback, not silently adopted).

> **REV 2026-07-28 (S1 build, coordinator ruling — no ADR earned, no contract/law change):**
> `dogfood-assets.ts`'s `DOGFOOD_JS` string literal embeds the fleet's OWN already-compliant minified
> bundle as opaque text; post-minification identifier names inside that text happen to spell
> `emit(e)`/`new CustomEvent($e)` etc., which `naming-gates.test.ts`'s Gate 1 (naming.md §4's emit-seam
> scanner) flagged as violations — a scanner false positive on DATA, not a real violation of authored
> source. Resolution: `naming-gates.test.ts`'s `walk()` gained ONE narrowly-scoped path exclusion for
> this exact generated file (`GENERATED_DATA_ARTIFACT_EXCLUSIONS`, one literal path, never a broad
> glob), following the SAME reasoning the walk already applies to `.test.ts` files ("not the fleet's
> real emitted/rendered surface") — a committed generated data artifact emits nothing; it carries
> bytes. naming.md §4's LAW is unchanged (a control still emits only the closed vocabulary); only the
> scanner's file-selection predicate gained a cited, single-path carve-out. GH #316/ADR-0162.

## 3. LLD-C2 — frame injection

- `props` gains `assets: { ...jsonType<SandboxFrameAssets>(), default: EMPTY_ASSETS, attribute: false }`
  — property-only (the `csp` precedent; asset text is never attribute-fed), safe codec, never
  throws. `SandboxFrameAssets = { css?: string; js?: string }`, exported beside
  `SandboxFrameCspConfig`.
- The build effect keys on `html`/`csp`/`assets`; `#build` passes assets through to `buildSrcdoc`.
- `buildSrcdoc(html, policy, tokens, colorScheme, assets?)`: after the existing three unshifts, when
  assets are present insert asset `<style>` after the token style and asset `<script>` after the
  bootstrap script — final head order per SPEC-R12: CSP meta → token style → asset style →
  bootstrap → asset script → model head children. (Mechanically: build the five nodes in an array
  and insert once, replacing the three-fold `insertBefore` chain — same result for the asset-less
  path, asserted byte-identical by the existing bootstrap tests.)
- `sandbox-frame.md` descriptor: the `assets` prop row + a dogfood note; descriptor/naming gates
  extended, never bypassed.
- An empty/absent `assets` renders a srcdoc BYTE-IDENTICAL to today's (regression-pinned in
  `bootstrap.test.ts`).

## 4. LLD-C3 — the prompt segment

- `genui-surface-config.ts`: `dogfood?: boolean` + doc comment (the `exclusive` shape).
- `dogfood-inventory.ts` (Node-side, `src/agent/`): reads
  `packages/agent-ui/components/src/controls/*/{name}.md` via the ONE ADR-0004 parser
  (`@agent-ui/components/descriptor` — a2ui already depends on components; import direction is
  lawful), `process.cwd()`-relative paths (the ADR-0135/TKT-0044 mechanics — never
  `import.meta.url`). Emits one line per control: `- <tag> — <summary> (attrs: name: type|enum, …)`,
  attributes truncated per control to the descriptor's declared set. Skips controls outside
  `DOGFOOD_TAGS`? No — see LLD-C5: the inventory derives from the SAME control set the bundle
  entry imports (the components barrel), and the set-equality gate holds the pair; the function
  takes the tag list as an argument so the gate can probe both directions.
- `system-prompt.ts` — `genuiBlock` gains the dogfood leg:

  ```ts
  const dogfood = genui.dogfood === true
    ? `\n\n${GENUI_DOGFOOD_TEACHING}\n\n## agent-ui components available inside your GenUI document\n\n${dogfoodInventory()}`
    : ''
  return `\n\n${GENUI_TEACHING}${exclusive}${dogfood}${source}`
  ```

  Order per the SPEC-R10 amendment: base teaching → exclusive → dogfood → source.
- `genui-dogfood-teaching.md` content contract (authored at build, budget ≤ 8 000 chars): the frame
  now ALSO contains the agent-ui runtime — prefer `ui-*` components and `--md-sys-*`/`--ui-*`
  tokens over hand-rolled HTML/CSS for anything the fleet expresses; attributes are the API (no
  framework imports — the elements are already defined); events per the closed fleet vocabulary;
  plain HTML stays legal for what the fleet lacks; the sandbox-reality rules above still bind.
- **Gates**: baseline gains a `genuiDogfoodTeaching` field (equivalence gate extends, the
  `genuiPacks` shape; recapture via the sanctioned scratch-spec flow); `prompt-drift.test.ts` gains
  the inventory leg (derived output ≡ descriptors; planted-phantom negative control); budget tests
  beside them; `genui-surface-prompt.test.ts` gains the SPEC-R10 AC3 cases (on/off byte-identity ×
  `exclusive` interplay).

## 5. LLD-C4 — plumbing + surfacing

- `chat-validation.ts` `validateGenuiSurface`: accept `dogfood` boolean, per-field degrade
  (the `exclusive` clause, copied); both transports inherit.
- agent-admin: the GenUI Surface Options row gains a `ui-switch` "Use agent-ui components"
  (Fisher-Price label; internal name `dogfood`) beside the source picker; persisted through the
  card's existing store discipline; the live runner passes it into `genui`; the conversation feed's
  frame mount passes the asset pair (imported from `@agent-ui/components/dogfood-frame` at the APP
  layer — `app` already imports `components`) when the toggle is on.
- `gen-ui-live.ts`: an options-strip toggle; `renderGenuiSurface` sets `host.assets` when on;
  the `/status`-gated request body carries `genui: { enabled: true, exclusive: true, dogfood }`.
- Live-apply law: next turn's prompt + next mounted/replaced surface reflect the toggle — no reload
  (frame REPLACE already rebuilds the whole srcdoc, so an existing surface re-renders with assets on
  its next envelope, never retroactively).

## 6. LLD-C5 — cross-half gates

- **Set-equality**: `DOGFOOD_TAGS` (committed, LLD-C1) ≡ the tags `dogfoodInventory()` teaches ≡
  the descriptor-bearing controls of the components barrel — one test, three-way, planted-extra
  negative control each direction (SPEC-R13 AC2).
- **Mode-off zero-regression**: the four baseline compositions pass UNCHANGED (no recapture); the
  asset-less srcdoc byte-identity pin (LLD-C2); agent-admin default-off store state renders the row
  byte-identically.
- **Containment re-proof**: SPEC-R12 AC2 runs the EXISTING browser containment/network probes
  against a dogfood-asset frame (components shard).

## 7. Risks / open

- **Bundle size** unmeasured until LLD-C1 runs (est. low hundreds of KiB minified). The asset
  module's generated header records the real numbers; if the pair lands implausibly heavy (> ~1 MiB
  JS), the fallback is a curated SUBSET entry (still set-equal by gate) — a build-time decision the
  decomposition flags back to design, not a silent trim.
- **jsdom vs real-engine split**: srcdoc composition/ordering is jsdom-testable; upgrade/paint/
  containment probes are browser-shard only (the standing split).
- **Recorded-transcript replay** without assets renders unstyled fleet markup — accepted, recorded
  in ADR-0162/SPEC-R10.
