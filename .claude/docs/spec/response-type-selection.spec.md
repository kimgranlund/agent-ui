## 1. Definitions

- Response type: `text` (a turn with no A2UI lines), `surface` (A2UI lines with an empty or caption-length text), `both` (a non-empty text followed by A2UI lines). Observed from the wire, never declared by the model.
- Terminal tool: a tool whose call ends the model's turn. The adapter executes it once and makes no further upstream request; its result never reaches the model in that turn.
- Text channel: the model's ordinary assistant text. Under this SPEC it is the user-facing reply; the leading meta-line (declarations) may still open it.
- Legacy shape: a text channel whose first non-empty line is an A2UI message (`{"version":...}`) or whose only content after a meta-line is A2UI JSONL. The pre-change grammar.
- Preference: `'text' | 'surface' | 'auto'`. The user override is per turn and mechanical; the persona hint is per agent and advisory.

## 2. Requirements

### RTS-R1: the `render_surface` terminal tool

`produce()` offers one tool on every turn where `a2uiEnabled !== false`, named `render_surface`, declared by `renderSurfaceTool()` in `src/agent/response-type.ts`. Input schema: `{ jsonl: string (required): the A2UI JSONL, one message per line; target?: string: the open surfaceId this payload updates }`. (REV 2026-10-14, T-0172: the schema is `{ messages: object[] (required), target?: string }`, one A2UI message object per entry, because a model hand-escaping JSONL inside a string unbalanced braces on live turns; `renderSurfaceJsonl` serializes `messages` to one line each and still reads a legacy `jsonl` string. A text round whose prose carries A2UI lines routes them as the payload, tallied `TEXT_JSONL_ROUTED`. REV 2026-10-14, T-0194: the schema adds a required `reply: string`, one short line to the user, because a Sonnet 5.5 greeting called the tool with no text and the chat showed only a message tally; when the round's text channel is empty the trimmed `reply` (`renderSurfaceReply`) is the outgoing `note`, and text in the channel still wins. REV 2026-10-16, T-0304: a `messages` sent as one JSON string is read as the array it holds, tallied `MESSAGES_STRING_DECODED`, because Haiku and Sonnet 5.5 sent one on every round of a turn in round 7. A string that does not parse is never edited (Kim 2026-10-16): it stays a PARSE round, and the repair names where it broke (`messagesParseNote`: the message still open where the next `{"version"` message begins, its kind and the `}` it lacks, else the JSON.parse position and the text there).) The description asks for an update over a create when one fits. (REV 2026-10-14, T-0206: the description is byte-stable across turns, because tools open the prompt-cache prefix; the open surfaces of the session (`sessionKnownSurfaceIds`) ride on the current user turn as `[Open surfaces: a, b.]` (`openSurfacesNote`), on every turn that offers the tool.) The tool is appended to the caller's integration tools; `tools` without `executeTool` is still "no tools" for the adapter, so `produce()` always supplies an executor that captures a `render_surface` input and delegates every other name to `opts.executeTool`.

- AC1: with `a2uiEnabled: false` the tool is not offered and the request shape is byte-identical to before this SPEC.
- AC2: a scripted provider that reports a `render_surface` tool round with `{jsonl}` reaches `produce()`'s executor exactly once; the executor's result text is `received` and is never fed back as a tool result within the turn.
- AC3: the serialized tool definition plus the grammar teaching added for it stay within the K6 room (PRD §6).

### RTS-R2: the seam gains `terminalTools` and `toolChoice`

`AgentProvider.stream` takes two additive, optional fields. `terminalTools?: readonly string[]`: a round that ends with a call to a named tool executes it, yields the round's text, and returns without a continuation request. `toolChoice?: { name: string }`: force that tool for the round when the provider supports it. An adapter that ignores either is byte-behavior-unchanged (the `effort?` precedent). The Anthropic adapter: when every declared tool is terminal, the round's text fragments are yielded live as they arrive (no scratch prose can follow a terminal-only round); with a mix of integration and terminal tools, text stays buffered per round as today and a terminal call ends the loop. `tool_choice` is sent only when the request sends no `thinking` parameter or sends `thinking: disabled` (the API forbids a forced tool choice with extended thinking; T-0301's forced repair round sends `disabled`); otherwise it is omitted and RTS-R6's correction round applies. REV 2026-10-16, T-0310 (Kim's R8 ruling, an experiment measured live): round 1 of a click turn (an A2UI action) with no live integration tool is forced the same way, `toolChoice` render_surface plus `thinking: disabled`, when the model's capability row takes a forced tool with thinking off at the turn's effort (`acceptsForcedToolWithThinkingOff`: Haiku 5.5 up to `high`); a typed turn and a Sonnet or Opus click send neither. REV 2026-10-16, T-0321 (Kim 2026-10-16): the repair round after a `SURFACE_DROPPED` round (one that answered in prose after an earlier round built a surface, or a valid one that left a built surface out) is forced the same way; round 8 :169 (Haiku) answered two such rounds in prose with thinking on.

- AC1: fixture-tested request bodies: `toolChoice` present with `effort` absent or `low` carries `tool_choice: {type:'tool', name}`; with `effort: 'high'` it carries none.
- AC2: a scripted SSE stream with a text block then a `render_surface` tool_use block yields the text fragments before the executor runs and makes one upstream request.
- AC3: a scripted stream with an integration tool_use then a text round still makes two requests and yields only the second round's text (the GH #49 law, unchanged).

### RTS-R3: the text channel is the reply; the leading meta-line stays optional

`produce()` reads the round's text channel as follows. The first non-empty line is peeled as the meta-line when `readMetaLine` accepts it (today's `peelMetaLine`). If the remaining text's first non-whitespace character is `{` and the line parses as an A2UI message, the round is the legacy shape and runs today's path unchanged (RTS-R4). Otherwise the remaining text, trimmed, is the reply; the outgoing meta-line's `note` is that text, else the captured `render_surface` `reply` (T-0194), else the model-authored `note`. The A2UI payload is the captured `render_surface` input's `jsonl`, run through `assembleFromRaw`, `stampCreateSurfaceCatalogId`, `validateA2ui` with the session seeds and `atFinalize: true`, the FEED_SCOPE gate, the semantic checks, the NET_NOOP detector and the ask-integrity rule, in that order, exactly as the legacy text payload is today. A round that both calls `render_surface` and carries A2UI or genui lines in its text channel ships the tool payload; the text-channel lines are dropped from the reply and tallied `TEXT_JSONL_IGNORED` on the trace.

REV 2026-10-16, T-0309 (Kim's N1 ruling): a text round with no payload that is closing-shaped (a note, no ask, no plan, no genui line), whose user message is an explicit close (`isExplicitClose`) and whose flow no persona check holds open, ships with `flowEnd: true` set by `produce()` and `FLOW_END_INFERRED` tallied, instead of the GH #1168 `FLOW_END_MISSING` repair round (r6's costliest code: on Opus, round 1 was already a correct close). It spends no round, so it also applies at `maxRounds: 1`. A semantic or narration finding still gets its repair round first, and a round that ships one uncorrected is not inferred closed. A turn that declares an ask is never inferred closed.

- AC1: a tool round `{jsonl}` with `then: "Here is your card."` ships `{"a2uiMeta":{"note":"Here is your card.",...trace}}` first, then the validated A2UI lines.
- AC2: a text-only round (no tool call, no JSONL) ships a note-only turn with `rounds: 1` and no A2UI line; it never halts.
- AC3: a round whose text opens with `{"a2uiMeta":{"ask":{"surfaceId":"ask-1"}}}` and whose tool payload creates `ask-1` ships the ask arm and the surface; the ask-integrity rule applies to the tool payload exactly as to a legacy payload.

### RTS-R5: text streams first as an additive meta arm

When the turn's declared tools are all terminal (no integration tool active) and the text channel is not the legacy shape, `produce()` yields `{"a2uiMeta":{"textDelta":"<fragment>"}}` per text fragment as it arrives, strictly ahead of any content line, after the leading meta-line (if any) has been peeled (fragments are held until the first newline or until the first non-whitespace character is known not to be `{`). The final leading meta-line still carries the complete `note`. `readMetaLine` gains `textDelta?: string` (shallow-validated like every arm: a non-string drops only itself). A2UI content lines never precede validation (SPEC-R5 unchanged: text is not content).

- AC1: a scripted provider yielding three fragments produces three `textDelta` lines, then the meta-line whose `note` equals their concatenation trimmed, then the content lines.
- AC2: with an integration tool active in the turn, no `textDelta` line is yielded and the note ships whole.
- AC3: `admin-live-runner.ts` yields a `{kind:'text-delta'}` event the conversation paints into the bubble and replaces on the final note; `a2ui-chat` and `a2ui-live` ignore the arm this wave and render as today.

### RTS-R6: user override, mechanical

`detectUserOverride(input: TurnInput)` in `response-type.ts` is a fixed lexicon over the `kind: 'intent'` arm only (the `isExplicitClose` precedent): a text override ("just tell me", "no card", "text only", "don't show", "skip the ui") and a surface override ("as a card", "as a table", "as a chart", plus "show me", "build", "build me" and "make me" only when a surface noun heads the phrase: an optional article, up to two modifiers (never "how", "what", "why", "where", "when" or an article), then form, card, table, chart, dashboard, panel, survey, calculator, checklist, widget, page, screen, list, plans, tabs, wizard or diagram, plural allowed, ending the phrase or followed by a preposition; "list of" and "of contents" never count). Phrases match on whole-word boundaries; text wins a tie. A request field `responsePreference` (validated fail-closed by `validateResponsePreference` in `chat-validation.ts`, the composer toggle's path) threads as `ProduceOptions.responsePreference` and has the same effect: it is the mechanical override, and `'auto'` means none. The intent lexicon beats it as the latest instruction. Text override: `render_surface` is not offered that turn. Surface override: `toolChoice: {name:'render_surface'}` when the provider can honor it; otherwise, if the round returns no payload, one correction round with code `SURFACE_REQUESTED` and a one-sentence hint, then ship as text with `SURFACE_REQUESTED_UNMET` tallied. The override beats the persona hint.

- AC1: a turn whose intent matches the text lexicon offers no `render_surface` tool (asserted on the request the stub provider receives), whatever `prefers` says.
- AC2: a turn whose intent matches the surface lexicon sends `toolChoice`; a stub that returns text only triggers exactly one correction round, then ships text with the tally.
- AC3: `responsePreference: 'text'` on the proxy request has AC1's effect; any other value than the three literals is dropped.
- AC4: "show me the capital of Finland", "Can you render my resume summary?", "what is a Render farm", "How do I build a house", "Please make me a sandwich recipe", "the render() function" and "tell me a story in words of one syllable" match neither lexicon; "show me a pricing table" and "Build a settings panel" still match the surface lexicon. "build a list of reasons", "make me a table of contents", "show me how a table join works", "show me what a card game looks like" and "build a wizard character" match neither; "show me a diagram", "Build me a form" and "show me a pricing tables" match the surface lexicon.

### RTS-R7: persona hint `prefers`

`ProduceOptions.prefers?: 'text' | 'surface' | 'auto'` threads to `buildSystemPrompt` as a tenth additive parameter composing one `response-preference` section from `prompts/response-preference-text.md` or `prompts/response-preference-surface.md` (byte-pinned, embedded by `generate-agent-assets.mjs`); `'auto'` and absent compose zero bytes. `prefers` is advisory only: it never changes the tool offer or `toolChoice`. - AC2: the schema default is `auto` and the runner omits the key when the value is `auto` (the `effort` absent-key precedent).

### RTS-R8: degrade to text at the round bound

## 5. Duplicate-root semantics, retry surface loss, structured tool input (T-0172, built)

Two failures seen in live traces on 2026-10-14 (`npm run traces`, T-0151) drove this section, one on the update turn, one in the self-correct loop, plus the PARSE rounds a hand-escaped `jsonl` string caused. The producer reference doc (`.claude/skills/a2ui-jsonl-mcp/references/producer-order-and-yield.md`, "T-0172 rules") carries the same rules.

### RTS-P1: a same-type root resend replaces the root

A2UI v1.0 `updateComponents` adds or updates components by id and sets no send-once rule for `root`, so the rule that landed is the upsert: a later turn's `root` of the SAME component type replaces the surface's root (`validate.ts` counts the seeded root as presence; `tree.ts` reconciles it onto the same element; runtime SPEC-R3 AC2 REV). A `root` of another type, or two `root`s in one payload, still fails `IDGRAPH <surfaceId>:root`, and the `duplicateRoot` hint names that repair: re-create the surface with the same id and the complete tree.

- AC1: the recorded Croupier deal turn and Concierge booking turn replay keyless through the real `produce()` (`scripts/e2e-admin/probe/replays/croupier-deal-halt` and `concierge-booking-surface-loss`), red before the change and green after. T-0222: the replay now runs the Croupier's semantic checks as the dev proxy does, and the recorded deal rounds halt again (BET_CONTROL_DUPLICATE on the recorded repair round, then PARSE), so `croupier-deal-halt` pins that halt; RTS-P1 itself stays covered by `live-agent/produce-loop.test.ts`.
- AC2: the producer reference doc states the rule, and the `duplicateRoot` hint agrees with it (`produce-loop.test.ts`).

### RTS-P2: a retry never silently loses a surface

At the top of each self-correct round, `produce()` takes the session-new surfaces the failed round created that no failure path names (`surfacesToKeep`), and the repair message asks to keep them by id. A later round that validates without one of them is not a success: it spends one `SURFACE_DROPPED` round naming the id, and on the last round halts with `SURFACE_DROPPED`. A surface a failure does name (an abandoned `createSurface`, a NET_NOOP) may be dropped by the repair. T-0281: a repair round that answers in prose alone, with no payload, after an earlier round of the turn built a surface it kept to its end (failure-named or not, the FEED_SCOPE retry's `ask-1`), is not a success either: the same `SURFACE_DROPPED` round names those ids, its hint says to resend the surface (as an ordinary surface with no `ask` when FEED_SCOPE sent it back), and the last round halts. T-0302: a last-round halt for a drop, a parse failure or a schema failure ships the last earlier round that validated and dropped nothing instead, tallied `EARLIER_ROUND_SHIPPED`; only a turn with no such round halts. T-0305: a round that updates (`updateComponents` or `updateDataModel`) a surface no earlier turn created, the client turn does not come from, and no earlier message of the round creates fails `SURFACE_NOT_CREATED` at that id on any round, the first included, and its hint asks for a `createSurface` first. The renderer drops such an update, and the shared validator opens the surface implicitly (it judges a standalone payload), so the check lives in `produce()` (`uncreatedSurfaceFailures`); the round 7 Haiku repair round that sent the BookingForm as updates to the `ask-1` only the rejected round created no longer ships. REV 2026-10-16, T-0317 (Kim's L1 ruling): the keep set is turn-scoped. Every session-new surface an earlier round of the turn built (created and gave components; a bare `createSurface` never became a surface, so the ADR-0187 repair may still drop it) is kept or explicitly deleted (`deleteSurface`) by the round that ships, failure-named or not; a valid round without one spends a `SURFACE_DROPPED` round, and at the bound the earlier round ships (T-0302) or the turn halts. The T-0172 allowance to drop a surface a failure names is gone. `surfacesToKeep` now only words the repair: a `parent->child` path names the surface whose `parent` lists that child, a component id delivered to several surfaces names them all, and a `SURFACE_DROPPED` path (a surface the round left out) names none of the round's own, so the keep hint never asks to keep a broken surface and never forgets a valid one. The property test `produce-loop-property.test.ts` holds no counterexample over every 2- and 3-round sequence. REV 2026-10-16, T-0321 (Kim 2026-10-16): the T-0302 fallback never ships a round a semantic check fails. At the bound it ships the latest earlier round that validated, dropped nothing and has no finding (judged as the last round would be, with the turn's binding composites); with none the turn degrades or halts as it would with no earlier round. This narrows T-0302's "a semantic finding never rules it out": round 8 :169 (Haiku) shipped a DescriptionList read-back BOOKING_FORM_MISSING had sent back, so the guest never saw the BookingForm. The repair round after a `SURFACE_DROPPED` round is forced (RTS-R2). Four recorded replays that shipped a flagged round now halt and one degrades to text (`concierge-haiku-orphan-update`). REV 2026-10-17, T-0328 (Kim 2026-10-17, amends T-0317): a surface rebuilt under a new id within the same turn is not a drop; only a surface that would have shipped counts. A built surface is protected once some round built it with no failure attributed to it alone (`flaggedSurfaces`, the T-0317 attribution built once a round). Every failure flags the one surface its path names, except `NARRATED_MECHANICS`, `FEED_SCOPE` (shippable, rescoped on the last round), `SURFACE_DROPPED`, `PARSE` and `NET_NOOP`; a path that names no surface or several flags nothing, so it protects. Each round, valid or not, that first builds an id no earlier round of the turn built retires, one per such id, the earliest-built surface it leaves out that every building round flagged; a retired surface is no longer tracked, so a chained rename retires one surface a round. Any other surface a valid round leaves out spends a `SURFACE_DROPPED` round as before, so a round that builds no new id drops a flagged surface too, and a prose round drops any tracked surface (T-0281). A round sent back only for `SURFACE_DROPPED` protects its own surfaces. Round 9 :1 (Haiku) built a Slider bet Card on `ask-1` (BET_TABLE_MISSING), rebuilt it as a CardTable on `table-1`, and halted; it now ships round 2. The replay `lexicographer-haiku-fleet-check` now ships its third round's `ask-2` board, and `concierge-booking-surface-loss` (round 2 builds no new id) still halts. REV 2026-10-17, T-0330: the `SURFACE_DROPPED` repair restates, per dropped surface, the latest missing-composite finding (T-0299) whose path names that surface id, as one sentence after the hint: "Earlier this turn `<sid>` failed: <message> Resend it fixed, not as it was." It does so only while the surface as last built still lacks the composite (`compositeAnswered`), and a renamed surface's own finding counts. ### RTS-P3: structured tool input; `strict` not used

`render_surface` takes `messages`, an array of A2UI message objects (RTS-R1 REV). That removes the cause of the PARSE rounds: the model no longer hand-escapes JSON inside a string. REV 2026-10-16, T-0311: it removed most of them, not the cause. In live round 7 (`.sdlc/evals/rounds/2026-10-16-r7-fails/report.md`, cluster A) Haiku and Sonnet 5.5 sent `messages` as one JSON string on every round of a turn, so each round was PARSE; T-0304 now reads such a string as the array it holds (`MESSAGES_STRING_DECODED`), and a string that does not parse stays PARSE with a located repair (RTS-R1 REV). `strict: true` is NOT set. Strict tool use requires `additionalProperties: false` on every object, so a component's props cannot stay open; a strict schema would have to declare every component's props per catalog (function-call `args` are open objects too) and meets the strict limits on optional parameters on the wider controls. The structured array plus the shared validator is the contract; a catalog-derived strict schema is a separate decision, not planned here.
