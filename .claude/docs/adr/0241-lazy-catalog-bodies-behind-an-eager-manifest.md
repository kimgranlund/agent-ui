## Context

GH #1811 asked why the `@agent-ui/app` marginal budget had to be raised and how to stop paying for catalog data. The premise was stale (T-0026 measured it on main@e3d03679). The gate is not red: `npm run size` exits 0 with the app row at 71,231 B gz against `APP_MARGINAL_BUDGET = 72,027`, 796 B of headroom. The budget was re-based down on 2026-10-05, and the ADR-0197 cl.5 exception closed when ADR-0233 stopped the catalog factories importing the 87-control fleet. What is still true, and is the reason for this record:

- ADR-0197 cl.5 closes upward re-bases of this row. The next feature wave has 796 B to land in.
- `renderer.ts` statically imports eight catalog modules (the default, a2ui-basic, the persona packages, the compose step and the control registry). A host that renders one catalog pays for all of them: 14,970 B gz, 21% of the app eager bundle, measured by leave-one-out and held to the byte by a harness that reproduces the gate's own figure.
- The a2ui `.` barrel is inert. With only `renderer.ts` edited, the surviving catalog modules in the app eager closure carry no bodies, so `surface-host.ts` keeps importing the public barrel and no subpath is needed.
- ADR-0233 already built the pattern for controls: a record table with lazy `import()` thunks, a loader, and a per-surface deferred-apply queue. Catalog bodies were left out of it.

Measured options, all against 71,231: lazy non-default bodies (the records mechanism with the default catalog kept eager and synchronous) -5,017 B gz; the same mechanism with the default catalog lazy too -14,064 B gz, which makes the default path asynchronous (26 test files and 13 non-test callers construct a renderer); a lazy renderer in `ui-surface-host` -26,695 B gz, a public-control timing change that needs its own ADR. The design (`.sdlc/size-budget-split-design/design.md`) recommends the first now and the second on a ruling. Kim chose the first only.

## Decision

1. **Catalog bodies load by catalog id, behind an eager manifest.** A catalog record is `register()`'s argument list split in two. The eager part is a manifest: the catalog id, a copy of the catalog's `functions` definitions, and the tags of its submit-gate factories. The lazy part is `load()`, an `import()` of the unchanged body module (document, factory table, optional function-impl table, optional control loader). The built-in records are an explicit list in `catalog/records.ts`, in the manner of `personas/index.ts`, with no generator: three bases, one alias and three personas do not earn a generator and a drift gate, so a bijection test replaces the drift gate.
2. **The default catalog stays synchronous (Option B).** `agent-ui` registers eagerly exactly as today. Moved behind records: `a2ui-basic` under both ids (the short id and the canonical URI), the three persona packages, and the compose step with them. `ui-surface-host`, `conversation`, the site and the tools do not change.
3. **The registry gains a lazy-record API; `register()` does not change.** `Registry.registerLazy(record)`, `knows(id)` (registered or recorded), `ensure(id)` (load and register into this registry, once), and unions in `supportedCatalogIds()` (loaded ids plus recorded ids, no duplicate once loaded) and `submitGateSelector()` (loaded factory tags plus recorded `submitGate` tags). `get(id)` still answers only for a loaded catalog. `register(catalog, factories, functions?, controls?)` and its last-wins semantics are the project-catalog seam (SPEC-R6, N1) and stay as they are. The new `CatalogRegistry` members are optional, so every existing caller and test double compiles unchanged.
4. **The load is memoized module-wide, the registration per registry.** Each `ui-surface-host` builds its own renderer, so a module-global "already registered" flag would leave the second renderer empty. The loader caches the promise of `load()` by record, and each registry registers the loaded body into itself once. A rejected load is dropped from the memo so the next call retries (the ADR-0197 cl.3 `loadAgentAdmin()` precedent). A `register()` or `registerLazy()` for an id that lands while its body loads wins (last-wins), and the late body is discarded.
5. **A failed load is one typed error.** The registry's `CATALOG_FACTORY_MISSING` gate still runs, now at load. Every failure on the load path (an unknown record, a rejected `import()`, a body whose document declares another id, a factory gap) rejects with a single `CatalogLoadError` carrying the catalog id and the cause. Slice 3 maps it to one surface-scoped `CATALOG_LOAD` per surface beside `CONTROL_LOAD`.
6. **The renderer defers `updateComponents` behind a catalog gate, built in the next slice.** `createSurface` on a known-but-unloaded id creates the surface and tree synchronously and kicks `ensure` immediately, so the chunk fetch overlaps the model's time to first token. `updateComponents` and `finalize` queue behind it in the ADR-0233 queue, with the catalog gate ahead of the control gate; `updateDataModel` follows the existing queued-once-a-queue-exists rule. An id that is neither registered nor recorded is still `CATALOG_UNKNOWN`, synchronously. A synchronous fast path holds once a body is loaded.
7. **`callFunction` must not depend on which bodies are loaded.** Its most-restrictive-wins `clientOnly` verdict (SPEC-R14, ADR-0034) reads the manifest's `functions` for an unloaded id. That is why the manifest carries function definitions. The implementation comes from the shared eager `catalogFunctions` table; the per-catalog override tables live in the lazy bodies and are read by binding evaluation once a surface exists.
8. **Persona composition errors move to load time for the shipped sets.** `CatalogComposeError` (SPEC-R2 AC3 and AC6) surfaces at load, not at construction, for shipped personas. The guarantee is kept by a CI test that composes every shipped persona against the real bodies, so a collision cannot ship. A persona a project registers itself still throws synchronously.
9. **The gates ship with the moves.** A manifest bijection test (record ids equal the shipped catalog folders, the alias and the persona-by-base ids; `record.functions` deep-equals each loaded body's `catalog.functions`; `record.submitGate` equals the body's submit-gate tags) and a bundle-shape test (a real Rolldown build of the app barrel: no body module in the eager closure, each in a non-eager chunk, which is also the `INEFFECTIVE_DYNAMIC_IMPORT` trip-wire). `APP_MARGINAL_BUDGET` re-bases down to the measured figure plus 2,048 B in the slice that moves the bodies, an ordinary downward re-base under ADR-0197 cl.5.
10. **The Option C trigger is recorded here so a later flip is a measured ruling, not a new design.** Making the default catalog lazy is one more record, a further -9,047 B gz measured, at the price of an asynchronous default path (a first render that waits for a 6.1 KB gz chunk, preloaded at renderer construction, and the 26 test files and 13 non-test callers listed in the design). It is taken only on Kim's ruling, for example when the app row's headroom falls under 2,048 B gz after this change lands.

## Consequences

- The app eager bundle shrinks by about 5.0 KB gz when the bodies move (measured on a prototype at -5,017 B), and a host that never renders `a2ui-basic` or a persona stops shipping them. The lazy chunks total about 15.8 KB gz for a host that loads every catalog, 1.7 KB gz more than today's eager figure (lost shared dictionary, chunk framing); any host that skips a catalog nets a saving.
- Slice 2 of this change adds the seam and removes nothing, so the app row grows by the seam's own bytes until the bodies move: measured 71,231 to 71,628 B gz (+397), headroom under the 72,027 B budget 796 to 399 B. It lands behavior-neutral: no caller, no test double and no wire shape changes. The renderer-side queue code of the next slice is estimated at +300 to 500 B gz, so that slice and the one that moves the bodies land together, or the first trims to fit; the budget does not move up.
- A rejected body load leaves the surface with queued messages and no catalog. What the queue does next (drain into the unknown-type path, or drop) is slice 3's decision, taken with the `CATALOG_LOAD` mapping.
- jsdom tests that ingest immediately and assert synchronously break for any lazy id. Six test files are named in the design's slice 4; the sync fast path holds once a body is loaded, and slice 3 gives tests an awaitable load.
- Not measured and deferred: the renderer-side queue code (estimated +300 to 500 B gz, re-measure before the budget re-base), the wall-clock cost of the first lazy fetch, and the per-renderer construction saving (a renderer today registers 3 catalogs and composes 6 derived ones).
- Repaired in the same change: pointers from ADR-0169 cl.2, ADR-0172 cl.2, ADR-0233 cl.5 and ADR-0197 cl.5. The SPEC, LLD and README repairs land with the slices that change what they describe, so a doc that says "constructor-time derive" or "registers on every renderer host" reads against this record until then.
- Open question for Kim, recommended no: whether project catalogs get a public `registerLazy`. `register` is unchanged and stays the only project seam; the new method on `Registry` is internal to the package, until a consumer asks.

## Alternatives considered

- **Raise the budget.** Rejected: ADR-0197 cl.5 closes it, and a budget change here is only the downward re-base.
- **Lazy documents only, factories eager (design Option A).** Rejected: it saves about what the records mechanism saves but pays the asynchronous default path for a third of the saving, because the default document is one of the lazy ones. `Registry.register` validates a document against its factory table, so registration still waits for the document, and every `entry.catalog` read needs it present. It is the records mechanism with the wrong scope.
- **Every built-in body lazy, default included (Option C).** Deferred, not rejected: it is the same mechanism plus one record, recorded in clause 10 as a ruling on a measured trigger.
- **A lazy renderer inside `ui-surface-host` (Option D, -26,695 B gz).** Rejected for this change: `connected()` creates the renderer synchronously and `ingest`, `onClientMessage` and `dispose` assume it exists, so it is a public-control timing change that needs its own ADR in the ADR-0197 mold, and it does not split catalog data from the renderer.
- **Fetch `catalog.json` at runtime from a static URL.** Rejected: it breaks the module graph and the ESM-CDN story (the ADR-0233 rejection of the same shape), adds an untyped integrity seam, and saves only 4.8 KB.
- **Deep-import the renderer in `surface-host.ts` to dodge the barrel.** Rejected: unneeded, because the a2ui barrel is inert, and SPEC-R2 AC4 pins that file to the public barrel.
- **A generator and drift gate for the catalog records.** Rejected: seven records do not earn one; an explicit list plus the bijection test is the same guarantee.
- **Pre-merge the derived persona documents at build time.** Rejected: six derived documents repeat the 44 KB default document, strictly more bytes.
