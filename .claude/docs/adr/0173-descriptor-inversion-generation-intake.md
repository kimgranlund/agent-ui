## Context

**The design problem** (GH #483's own summary, verbatim): *"Today each control's `{name}.md` descriptor is a hand-authored MIRROR of `static props`, held honest by three-way trip-wire tests... Invert it: the descriptor becomes the single SOURCE, and the mirrors become build artifacts — the `static props` block (or its type layer), the catalog row's PropDef/marks, and the site API page all GENERATE from one descriptor document."* Why now (issue, verbatim): *"every widening this arc (ADR-0161's three-slot marks, ADR-0163's prop growth, ADR-0169's rows, the coming M-D fragments) paid a manual mirror tax across 3-4 surfaces."*

This intake freezes the four questions the dispatch named, each argued from the real parser/gate/catalog mechanics verified in-tree below — not from the issue's own framing taken on faith. **One premise correction lands in cl.2: the site-API-page leg of the issue's own three-artifact list is already built**, predating this intake.

### The descriptor parser — what's already machine-complete (ADR-0004's instrument)

`packages/agent-ui/components/src/descriptor/component-descriptor.ts` is the ONE parser/schema/trip-wire module (its own header comment, `component-descriptor.ts:1-24`) — no YAML dependency, a hand-rolled indentation-scoped reader over a controlled subset. Three layers exist today, all TOTAL (never throw; return structured failure arrays):

- **`parseDescriptor`/`splitFrontmatter`** (`:53-186`) — reads the frontmatter fence into `topLevelKeys`/`scalars`/`sequences`/`maps`, plus a typed `attributes[]` view (`ParsedAttribute`: `name`/`type`/`values`/`default`/`reflect`, `:33-39`, `:154-168`).
- **`validateComponentDescriptor`** (`:253-316`) — the STRUCTURAL schema: `FIELD_SHAPE` (`:216-231`) fixes the full field set — `tag`/`tier`/`extends`/`forcedColors` (scalar), `attributes`/`properties`/`events`/`slots`/`parts`/`customStates`/`keyboard` (sequence), `face`/`aria`/`geometry` (map) — and `ATTR_TYPES = ['enum','boolean','number','string','json']` (`:234`) is the closed attribute-codec vocabulary. This is the machine-complete half in full: every one of these fields already parses into a typed, queryable shape.
- **`compareDescriptorToProps`** (`:439-483`) — the contract↔props trip-wire: NAME bijection, then per matched name TYPE (`kindOf`, `:383-409`, recovered by BEHAVIOR-PROBING the live codec — it has no kind tag), DEFAULT, REFLECT, VALUES.
- **`compareDescriptorToSource`** (`:560-581`) — the contract↔SOURCE trip-wire, for the two facts NO `static props` row carries at all: `customStates` (imperative `internals.states?.add()` calls + `:state()` CSS, `:490-493`) and CSS-only `slots` (`[slot='x']` selectors, `:494-496`). This layer exists BECAUSE these facts have no class field to read — proof, in the parser's own design, that behavior/CSS anatomy is genuinely one-directional (source → descriptor) and always will be.

A real per-control instance: `table-descriptor.test.ts` (LLD-C9, `:16-17`) runs all three layers against `table.md`/`table.ts`/`table.css` — structural validity (`:30-72`), the props trip-wire including negative controls (`:74-163`), events/parts vocabulary (`:165-180`), and the source trip-wire with negative controls (`:215-238`). Two more folders confirmed carrying the same pattern: `stat-descriptor.test.ts`, `form-provider-descriptor.test.ts`. `grep -rl "satisfies PropsSchema" packages/agent-ui/components/src/controls` counts **70** control files carrying a `static props` block — the mirror-tax population this intake scopes against.

**The prose body stays free markdown, by design, one-directional.** `splitFrontmatter` (`:53-56`) separates the fence from a `body` string; `site/lib/doc-page.ts`'s `renderMarkdownBody` (`:292-396`) renders it with a small dependency-free markdown subset (headings/lists/blockquotes/code fences/inline code+bold). This is the genuinely-prose half GH #483's own "Shape" section anticipates ("marks, codecs, enums, reflection flags are already structured... prose sections stay prose") — confirmed correct, not requiring any grammar growth.

### Two real grammar gaps the frontier needs to grow through (found, not invented)

1. **Attribute-name overrides have NO descriptor field, and the EXISTING trip-wire is blind to them.** `table.ts:123`: `pageSize: { ...prop.number(0), attribute: 'page-size' }` — the live `PropConfig.attribute` can diverge from the prop's own JS name. `ParsedAttribute` (`component-descriptor.ts:33-39`) and `FIELD_SHAPE`'s `attributes` sequence (`:216-231`) carry no `attribute:` field at all, and `compareDescriptorToProps` (`:439-483`) checks NAME/TYPE/DEFAULT/REFLECT/VALUES only — never the DOM attribute string. This is a real, pre-existing blind spot (not introduced by this ADR) that any props-generator must close first: without it, a generated `static props` block for `pageSize` would either omit the override or require inventing where to source it from.
2. **The codec KIND the descriptor names is not the codec IDENTITY a generator would need to emit.** `table.ts:105-125`'s `const props = {...}` mixes two shapes: (a) bare `prop.string('')`/`prop.enum([...], '')`/`prop.number(0)` factory calls (`props.ts:104-120` — the full closed factory set: `string`/`number`/`boolean`/`enum`/`json`), mechanically regenerable from `type`+`default`+`values`+`reflect` alone; and (b) bespoke hand-rolled codecs — `tableColumnsProp`/`tableRowsProp`/`tableSelectedProp`/`tableSortProp`/`tableFilterProp`, imported from a sibling `table-model.ts`, each encoding real structural validation/sanitization the descriptor's `type: json` only proves the RUNTIME SHAPE of (`kindOf`'s array-hardened-codec branch, `:388-391`), never which function to call. `grep -rlE "jsonType|safeArray|hardened" packages/agent-ui/components/src/controls/*/*.ts` finds **13 of 70** control files using this bespoke-codec shape. Regenerating `static props` for these 13 would require a NEW descriptor field naming a codec import — a real, non-trivial grammar widening this intake does not resolve (Decision 1, Open fork OF1).

### Generation direction, verified per artifact

**Target 1 — the props type layer (`static props`).** No generator exists today. Verified generatable, with zero new grammar beyond gap 1 above, for the ~57/70 controls whose entire prop set uses bare `prop.*` factories. The 13 bespoke-codec controls need gap 2 closed first (or stay permanently hand-authored — Open fork OF1).

**Target 2 — the catalog row's PropDef/marks.** `packages/agent-ui/a2ui/src/catalog/catalog.ts:65-88` — `PropDef` is `{ type: JsonSchema; bindable?: boolean; mapsTo: string; format?: string; rejectFunctionCall?: boolean }`. Verified against `packages/agent-ui/a2ui/src/catalog/default/catalog.json`'s `Table` entry (`:427-448`): scalar-shaped props (`label`, `selectable`, `rowKey`, `page`, `pageSize`, `search`) map cleanly to `{"type":"string"}`/`{"type":"string","enum":[...]}`/`{"type":"number"}` — mechanically derivable from the descriptor's `type`/`values` today. But three real gaps make this a HARDER target than Target 1:
   - **`bindable` has no descriptor analogue at all** — every PropDef in the catalog declares it, the descriptor schema has no field for it.
   - **`mapsTo` is not reliably `=== attribute name`.** A direct scan of `default/catalog.json` (`python3` walk over every `ComponentDef.properties`) finds **16 properties across the default catalog** where `mapsTo` diverges from the wire property name — e.g. `Text.text → textContent`, `Button.label → textContent`, `Icon.name → glyph`, `Stat.value → figure`. A generator cannot assume 1:1 correspondence; the diverging rows have no descriptor-side representation of the rename at all.
   - **Object/array-shaped (`json`-kind) props carry no derivable NESTED schema.** `Table.columns`' catalog PropDef declares a full nested JSON-Schema (`items.properties.key/label/type`, required array — `catalog.json:429-432`); the descriptor only records `type: json` (a behavior-class tag, `kindOf`'s probe result) — there is no descriptor field expressing object/array shape at all. Generating this leg would require embedding real JSON-Schema fragments in the descriptor grammar — a substantially bigger widening than Target 1's gap 2, out of scope for this intake (Open fork OF2).
   - `format`/`rejectFunctionCall` are sparse, single-consumer extensions (ADR-0114 cl.3; ADR-0169 E7/GH #429) with no descriptor analogue and no volume argument for adding one yet.

**Target 3 — the site API doc page. Already built; this intake corrects the issue's premise, not designs new work.** `site/lib/doc-page.ts`'s `composeDocPage` (`:267-277`) and its five table renderers — `renderApiTable` (attributes, `:137-146`), `renderPropertiesTable`/`renderEventsTable`/`renderSlotsTable`/`renderPartsTable` (`:227-258`) — already render straight off the SAME `ParsedDescriptor` the contract trip-wire validates (the file's own header comment, `:1-10`: *"the published surface IS the contract, not a hand-transcribed copy"*). `grep -rln "composeDocPage" site/pages` counts **54 of the ~70** control `*-doc.ts` pages already wired to it. What stays genuinely hand-authored per page — and correctly so, per the same header comment — is the anatomy-diagram markup, live specimens, and per-page wiring: underivable SHAPE, not mirror tax. **No new generation step is needed for this artifact.**

**What CANNOT generate, full stop.** `compareDescriptorToSource`'s own existence (`:485-503`) is the proof: `customStates` are added IMPERATIVELY (`.states?.add('ready')` behind `requestAnimationFrame`) and `slots` are positioned PURELY in CSS (`[slot='leading']`) — neither has a class field a generator could read FROM. Behavior code (event handlers, DOM construction, trait wiring) and CSS anatomy stay strictly source → descriptor, hand-kept honest by the EXISTING, unmodified trip-wire.

### The precedent: docs-as-derived-build-artifacts, already shipping in this repo

**Confirmed real, not taken on the issue's word.** `scripts/generate-llms-full.mjs`'s `generateLlmsFull` (`:45-`) walks every control's `{name}.md`, splits its fence, and derives `site/public/llms-full.txt` — the exact same descriptor sources this ADR's targets would read. `site/lib/llms.test.ts` G1 (`:23-42`) is the drift gate: it imports the SAME `generateLlmsFull` the CLI script runs (no generator/gate drift pair possible), asserts `expect(committed).toBe(fresh)` (`:36`), and its own header comment names the remediation (`:9`: *"Regenerate: `node scripts/generate-llms-full.mjs`"*). Critically, **this gate is NOT wired into `npm run check`** (`package.json:12-15` — `check` is `tsc && check:site && check:tools && check:scripts`, none of which touch `llms.test.ts`); it fires under plain `npm test` (vitest), where every other descriptor-consuming test already lives. This is the exact mechanical shape Decision 3 below reuses for the migration sequencing.

**S9 (`site/lib/docs-grammar.test.ts:118-131,197,241-267`), confirmed real, is a distinct and weaker precedent — cited to avoid over-claiming it.** S9 sweeps `.claude/skills/*/SKILL.md` tables for backticked repo-relative exemplar paths and `existsSync`s each (SPEC-R11, `saas-data-workbench.spec.md:264-268`). It proves "a cited path must resolve," not "an artifact regenerates and diffs byte-identical" — the llms-full.txt gate is the load-bearing precedent for this ADR's Decision 3, S9 is background corroboration only.

`.claude/skills/agent-ui-component-packaging/SKILL.md:26,40-42` already names the descriptor as packaging-shape law with "one parser, two consumers — the contract trip-wire and the site" — this ADR adds a third and fourth consumer class (a props generator, a catalog generator), not a new instrument.

## Decision

### 1 · The descriptor grammar's machine-complete subset

**Ruling: the existing grammar (`FIELD_SHAPE` + `attributes[]`'s five columns) is already the machine-complete subset for everything `static props` and the site API page need; it does NOT yet cover two facts a props-generator needs, and does NOT cover the catalog-only vocabulary a PropDef-generator needs at all.** No new grammar is invented here — this clause names the exact frontier, cited above:

- **1a — attribute-name overrides** (gap 1): a new optional `attribute:` column on `attributes[]` rows, parallel to `PropConfig.attribute`. Small, mechanical, and closes a real existing trip-wire blind spot as a side effect (independent value, Non-goals notes it as its own possible follow-up).
- **1b — codec identity** (gap 2): closing this for the 13 bespoke-codec controls requires either (i) a new field naming a codec import, or (ii) ruling those controls PERMANENTLY out of props-generation (a named, grep-able escape hatch). This ADR does not choose — **Open fork OF1**.
- **1c — catalog-only vocabulary** (`bindable`, `mapsTo`-divergence, nested JSON-Schema for object/array props): NOT a small widening — embedding real JSON-Schema fragments is architecturally bigger than 1a/1b. This ADR does not commit to building it — **Open fork OF2**.

**Why not treat the whole frontier as "already there, just describe it" (rejected).** The dispatch's own framing invited checking whether the machine-readable half already covers what generation needs; it does not, fully — 1a/1b/1c are real, found gaps, not assumed ones. Asserting completeness without the grep/JSON-walk evidence above would be exactly the citation-on-faith failure `agent-ui-doc-standards` §3's re-derivation discipline exists to catch.

### 2 · Generation direction + artifacts

**Ruling: three targets, three different postures.**

- **Site API doc page (Target 3): NO generation work needed — already shipped** (`doc-page.ts`, 54/70 pages wired). This ADR's contribution here is corrective: GH #483's three-artifact framing is stale on this leg; a future SPEC should not re-scope it as new work.
- **Props type layer (Target 1): the intake's real, buildable first target.** Direction is descriptor → `static props`, for controls whose attributes are all plain-codec (~57/70) once gap 1a closes. The 13 bespoke-codec controls are explicitly OUT of this target's first slice (Open fork OF1 decides their eventual fate).
- **Catalog PropDef (Target 2): named, not committed.** The mechanics exist for scalar-shaped, non-diverging properties; `bindable`/`mapsTo`-divergence/nested-schema gaps (1c) make a full-catalog generator a substantially bigger, later effort. This ADR records the mechanics and its real cost, and leaves WHETHER/WHEN to build it as **Open fork OF2** — a design intake's job is to freeze what's known, not manufacture a commitment the mechanics don't yet support.

**Why not generate the descriptor FROM `static props` (the reverse direction) — rejected.** `static props` and `PropDef` are both narrower than the descriptor: neither carries `aria`, `keyboard`, `geometry`/`tier`, `customStates`, `parts`, `forcedColors`, or the prose body — all real descriptor fields with no props-layer or catalog-layer source at all (`FIELD_SHAPE`, `:216-231`). The descriptor is the information-richer document; only descriptor → mirrors is coherent, exactly ADR-0004's original "descriptor is the contract" framing and GH #483's own chosen direction.

**Why not ship all three targets simultaneously in one build (rejected).** Target 3 needs nothing; Target 1 needs one small grammar addition (1a) plus a fork ruling (OF1); Target 2 needs a fork ruling with real architectural weight (OF2) before any implementation is safe to start. Bundling them would either stall Target 1 behind Target 2's harder, unresolved questions, or (worse) rush Target 2's JSON-Schema-embedding decision to avoid blocking Target 1 — exactly the "manufacturing a decision the mechanics don't support" failure this intake exists to avoid.

### 3 · Migration path for ~70 existing descriptors

**Ruling: per-control ratchet, reusing the llms-full.txt mechanism exactly — a control's trip-wire and its generator-drift gate are never both absent, because the SAME commit that adds the generated artifact and its drift test also retires that control's old hand-authored block.** No repo-wide flag day; no coverage-gap window.

Concretely, per control, in one PR:
1. The control's `static props` block is replaced by a generated block (or a committed generated file the control imports), produced by a new script mirroring `generate-llms-full.mjs`'s shape (pure function, deterministic, imported by both the CLI entry and its own test).
2. A new drift-gate test (mirroring `llms.test.ts` G1) asserts the committed generated output is byte-identical to a fresh regeneration off that control's `{name}.md`.
3. The control's EXISTING `compareDescriptorToProps` trip-wire test either retires (props are now generated FROM the descriptor, so drift is structurally impossible — the byte-diff gate subsumes it) or is kept as a redundant belt-and-braces assertion for one control as a canary before the pattern retires it fleet-wide (a build-team LLD call, not frozen here).

**Sequencing.** Start with the ~57/70 plain-codec controls (Target 1's first-slice population, cl.2) — mechanically ready once gap 1a lands. The 13 bespoke-codec controls stay on the old hand-authored+trip-wire path, untouched, until Open fork OF1 resolves. Target 2 (catalog PropDef) migrates independently and strictly later, per Open fork OF2.

**Why not a big-bang rewrite across all 70 (rejected).** Each control's descriptor+test pair is independently shaped today — `table-descriptor.test.ts`'s three-layer LLD-C9 pattern is denser than a simple control's; a fleet-wide flag day risks exactly the coverage-gap window this clause is asked to avoid (a period between disabling old trip-wires and having new generators fully proven across 70 heterogeneous files). The llms-full.txt precedent proves the safer shape already works at real scale (41+ descriptor sources) without needing a flag day.

**Why not "generate first everywhere, keep the old trip-wire running in parallel indefinitely" (rejected as the STEADY STATE, though legitimate as a transitional step).** Running both forever defeats the mirror-tax argument that motivates this intake — the trip-wire's whole cost is the SECOND hand-authored surface it compares against; once generation exists, keeping that surface hand-authored just to keep comparing against it re-introduces the tax it was meant to remove. Retiring the trip-wire per-control, in the SAME commit as its generator lands (as ruled above), is the version that actually converts "drift detector" into "build step that cannot drift by construction" — the issue's own framing.

### 4 · The failure model

**Ruling: extend the EXISTING three-tier failure discipline (thrown parse error → TOTAL coded schema/drift arrays → named vitest assertion) with one new tier for generation-time underivability; never introduce a silent or best-effort path.**

- **Parse-time** (`splitFrontmatter`, `:53-56`): unchanged — a missing/malformed frontmatter fence throws `Error('source has no leading --- frontmatter fence')`. Appropriate: a generator has no structured input to proceed from at all.
- **Schema-time** (`validateComponentDescriptor`, `:253-316`): unchanged in SHAPE — stays TOTAL, returns `DescriptorFailure[]` with stable codes (`MISSING_FIELD`/`BAD_SHAPE`/`BAD_TAG`/`BAD_TIER`/`BAD_EXTENDS`/`BAD_ATTRIBUTE`/`BAD_FACE`, `:205-206`). Any new field from cl.1a grows this same enum with new codes (e.g. a malformed `attribute:` override) — the pattern, not the code list, is frozen here. A future generator's CLI entry must call this FIRST and refuse to emit anything when `.length > 0`.
- **Generation-time (the new tier).** A descriptor can be schema-valid yet still be UNGENERATABLE for a specific target — a `json`-typed attribute with no codec reference (Target 1, gap 1b unresolved) or an object-shaped attribute with no embeddable schema (Target 2, gap 1c). This must be its own TOTAL, coded failure class (e.g. `GEN_CODEC_UNRESOLVED` / `GEN_SHAPE_UNDERIVABLE`) reported the same structured way — never a thrown exception the generator swallows, and never a silent fallback to a stale or partial artifact. A control ruled permanently out of generation (Open fork OF1's escape-hatch branch) must be named EXPLICITLY in the descriptor or generator config, so "why didn't this control's props generate" is answered by `grep`, not archaeology.
- **Gate-time** (the drift test, cl.3): unchanged from the llms-full.txt precedent — a plain `expect(committed).toBe(fresh)` byte-equality assertion, with a one-line regenerate command in the SAME describe-block comment convention `llms.test.ts:1-9` already uses.
- **Who sees it, and when.** No new channel: `npm test` is already where every descriptor-consuming gate lives (the per-control trip-wire tests, `llms.test.ts`). A control author sees a red, named vitest assertion with a stable code and a remediation line — never a green build with wrong bytes. This is the concrete cash-out of the issue's "cannot drift by construction" framing: not the absence of a check, but the same check, moved one step earlier (verified at generation, not compared after-the-fact between two independently hand-authored surfaces).

## Non-goals (recorded, not silent)

- **No generator implementation, no `attribute:` grammar addition, no codec-reference field, no JSON-Schema-embedding widening.** This intake freezes ARCHITECTURE per cl.1-4; building any of it is a future SPEC/LLD.
- **No fix to the attribute-name-override blind spot in the EXISTING trip-wire** (cl.1a's finding: `compareDescriptorToProps` doesn't check `attribute:` overrides today, independent of generation ever landing). Real, pre-existing, worth its own small follow-up regardless of this ADR's fate.
- **No migration of any of the 70 controls.** Cl.3 rules the sequencing, not the execution.
- **No change to `generate-llms-full.mjs`, `llms.test.ts`, or S9** — both cited as precedent only, untouched.
- **No scheduling.** GH #483's own Provenance: *"Not scheduled — an intake candidate for a future wave."* This ADR does not claim a milestone.

## Consequences

- GH #483 gains a ratified architecture for its most tractable leg (props-layer generation, Target 1) with a concrete, precedent-proven migration mechanism (cl.3) — but NOT a green light for the other two legs as originally framed.
- The site-API-doc-page leg of the issue's own three-artifact list is corrected on record as ALREADY SHIPPED — a future SPEC that re-scopes it as new work will be working from a stale premise if it doesn't read this ADR first.
- The catalog-PropDef leg is proven substantially harder than the issue's framing suggested (mapsTo divergence in 16 real rows, no `bindable` analogue, no nested-schema representation) — very likely a separate, later-landing generation target, not a simultaneous three-artifact ship.
- Two new, real, independently-fixable descriptor-grammar gaps are on record (1a attribute-name overrides, 1b codec identity) — a future props-generator SPEC/LLD inherits them as named prerequisites, not surprises.
- `.claude/skills/agent-ui-component-packaging` currently names the descriptor's "one parser, two consumers" (trip-wire + site) — a generator lands a third/fourth consumer class; the skill needs a forward-pointer note at minimum on ratification, a full pattern write-up waiting for the future build (Repairs cell, on ratification+build).

## Open forks

- **OF1 — Codec-identity closure (cl.1b).** For the 13/70 bespoke-codec controls, does the descriptor grammar widen with a codec-reference field (letting them fully generate, eventually), or are they ruled a PERMANENT, named escape hatch (never generated, forever hand-authored + trip-wired)? No in-tree precedent settles this — it is a real cost/benefit call (a codec-reference field is a bigger, more invasive grammar change than 1a) genuinely Kim's to make, not derivable from the mechanics alone. Flagged for a future SPEC.
- **OF2 — Whether catalog-PropDef generation (Target 2) is built at all, and if so, on what timeline relative to Target 1.** The mechanics found here (mapsTo divergence, no `bindable` field, no nested-schema representation) make this a genuinely bigger, separately-scoped effort than Target 1. Building it, deferring it indefinitely, or scoping a reduced version (e.g. only scalar-shaped, non-diverging properties) are all reasonable — a sequencing/ambition call, not something the mechanics alone resolve. Flagged for a future SPEC or standalone GitHub issue, Kim's call on which and when.

## Alternatives considered

- **Do nothing / keep the three-way hand-mirror indefinitely** — rejected on the issue's own load-bearing cost argument (every widening arc pays the tax across 3-4 surfaces); not reopening that framing here, it is the trigger, not a live alternative.
- **Generate the descriptor FROM `static props`/`PropDef` (reverse direction)** — rejected in cl.2: the descriptor is the information-richer document (aria/keyboard/geometry/customStates/parts/prose have no source anywhere else); only descriptor-as-source is coherent.
- **Ship all three artifacts as one simultaneous generation wave** — rejected in cl.2: the three targets have genuinely different readiness (Target 3 done, Target 1 one small gap away, Target 2 architecturally heavier) and bundling would either stall the easy win or rush the hard fork.
- **Big-bang rewrite of all 70 descriptors' generation status in one wave** — rejected in cl.3: real risk of a coverage-gap window across 70 heterogeneous files; the llms-full.txt precedent proves the safer per-control ratchet already works at comparable scale.
- **Keep both the old trip-wire and the new generator running forever, per control, as the permanent steady state** — rejected in cl.3: defeats the mirror-tax argument that motivates the whole intake; legitimate only as a transitional canary step for one control, not the end state.
