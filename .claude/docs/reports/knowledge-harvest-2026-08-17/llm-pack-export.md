## chat-harness-workflow-facts

1. **Bound the generate→validate→self-correct loop and emit NOTHING invalid: validate-then-stream.** The producer loop retries with fed-back failures up to `maxRounds`, then throws a typed halt (`ProduceHalt`) carrying the last round's failures — the client shows "could not compose" rather than a broken render; no partially-valid content ever reaches the wire. · `packages/agent-ui/a2ui/src/agent/produce.ts:1-12,306-314` (SPEC-R5, ADR-0070) · 2026-08-17 · [verified]
2. **Feed validator failures back as structured, self-correcting prompts — code + path + expected value, never a bare code.** A failure code alone ("CATALOG at lbl_in.emphasis") taught the model nothing; live repros showed identical wrong guesses across whole retry rounds until the feedback named the expected type/enum resolved from the catalog and the model's own prior output. · `produce.ts:515-544` (`expectedTypeNote`, GH #288/#397) · 2026-08-17 · [verified][incident]
3. **Static repair hints per failure class beat generic "re-emit corrected output".** PARSE failures (pretty-printed JSON across lines, trailing prose, a literal `</parameter>` tool-tag bleed-through at temp 0.9) and IDGRAPH failures (duplicate root, missing root, dangling ref, cycle) each repeat identically under generic feedback; a per-member static hint naming the concrete repair breaks the loop. Order the safe repair FIRST — a hint opening with "send only what changed" invited compliant rounds shipping unparented orphans that validate but never render. · `produce.ts:392-479` (PARSE_HINT, IDGRAPH_HINTS incl. the review-F1 ordering note; GH #307/#404) · 2026-08-17 · [verified][incident]
4. **Pin the user-visible reply's audience inside the correction loop.** Without an explicit instruction, a compliant model narrates its compliance in the user-facing note ("Re-emitting the corrected, validated JSONL…", observed live). Every retry prompt must restate: the note addresses the USER, in persona, never the correction machinery. · `produce.ts:349-355,497` (GH #174) · 2026-08-17 · [verified][incident]
5. **Empty ≠ invalid: a note-only turn (prose reply, zero structured payload) is a CLEAN success, not a halt.** Distinguishing "the model chose to answer in prose" from "the model failed to produce valid output" prevents burning retry rounds on legitimate conversational turns. · `produce.ts:7-9` (ADR-0088) · 2026-08-17 · [verified]
6. **Keep the session client-held and the server stateless; frame client events as natural-language user turns in ONE pure function.** The browser holds the `Session` (an ordered `{role, content}[]`); UI events (action / functionResponse / error) become the next user turn via a pure reducer (`nextTurn` + `frameClientMessage`), each arm framed distinctly so the agent knows what happened. Framing lives in one place, so producer and transports never disagree. · `packages/agent-ui/a2ui/src/agent/session.ts:1-98` (SPEC-R8, ADR-0072) · 2026-08-17 · [verified]
7. **Give UI actions a per-action "does the agent need to hear this" bit, checked BEFORE constructing a turn.** `shouldRunTurn` gates whether a client event becomes a conversational turn or applies silently (the surface's data model already updated locally); the default is opt-OUT (absent ⇒ full turn) for back-compat. Deliberately not folded into the reducer, so a caller can never build a turn for a message that should have stayed silent. · `session.ts:80-98` (ADR-0088 §3) · 2026-08-17 · [verified]
8. **Editing a settled answer appends an amendment turn; never rewrite or rewind the transcript.** A settled questionnaire answer's change appends "Changed: X → Y" as a new user turn the agent reconciles FORWARD; prior turns are never rewritten or removed — rewind falsifies the record the agent reasons over, and removal orphans the Edit affordance's anchor. Re-confirming the same answer appends nothing. · ADR-0196 cl.5 (`.claude/docs/adr/0196-…`) · 2026-08-17 · [verified]
9. **"Answered" is not "disabled".** Settling a form/question by hard-disabling its inputs reads as broken/forbidden and forecloses correction (a shipped-and-retired posture, GH #805); the replacement is a dedicated answered/settled visual state that keeps the control focusable and routes changes through an explicit Edit affordance. Precedence: `disabled > pending > answered > affordance states` — an answered control must not repaint to live-entry colors on hover, or the UI re-advertises interactivity the settle flow removed. · ADR-0196 cl.1-4 · 2026-08-17 · [verified]
10. **Stale-while-revalidate needs a fleet-wide pending convention, not per-component hacks.** Async surfaces keep rendering the last settled value dimmed (one opacity token, one host state) while a new answer streams — opacity, not color-repoint, because stale content is arbitrary unknown-depth DOM a token repoint can't reach. One state law per axis; new axes compose with, never reopen, closed tables. · ADR-0191; trait at `packages/agent-ui/components/src/traits/pending-computed.ts` · 2026-08-16 · [verified]
11. **Let the model declare its own plan as data, but keep execution host-side.** A `plan: {steps:[{id, description}]}` declaration rides the reserved meta envelope, model-authored, passed through unchanged with no runtime rewriting; the host-side plan→execute→synthesize loop is a separate contract. Declaring intent and executing it are different trust levels. · `packages/agent-ui/a2ui/src/agent/meta-line.ts:76-90` (ADR-0174/SPEC-R20) · 2026-08-17 · [verified]

## chat-harness-routing-facts

12. **Reserve an out-of-band envelope on the SAME stream via a provable structural discriminator.** Meta-lines (notes, traces, progress, errors) ride the same JSONL stream as content, distinguished by carrying the reserved wrapper key and provably NO `version` key — the protocol discriminator — so a meta-line can never be mistaken for a protocol message and vice versa. Framing conventions ride BESIDE a protocol, never inside it. · `meta-line.ts:185-207` (ADR-0088) · 2026-08-17 · [verified]
13. **Shallow-validate envelope fields independently: a malformed field drops ONLY itself, never the whole envelope.** A broken `ask`/`plan`/`progress`/`personaPatch` never breaks the conversational `note` channel it rides with — each arm degrades independently. (Exception: a compound arm like a persona patch validates as a WHOLE — a half-parsed patch is the one shape an apply loop must never receive.) · `meta-line.ts:199-304` · 2026-08-17 · [verified]
14. **Peel reserved line kinds BEFORE the content validator ever sees them.** The leading meta-line and any genui-shaped line are stripped from raw model output ahead of heal/validate — otherwise a legitimate note line burns a self-correct round as a parse failure. A reserved kind is peeled unconditionally, whether or not this turn invited it: stream handling never branches on prompt-composition flags. · `produce.ts:583-681` · 2026-08-17 · [verified]
15. **Closed vocabularies + drop-at-guard is the honesty law for progress/status streams.** Turn lifecycle stages are a closed union (`sent…done`); an out-of-vocabulary stage is dropped at the parse guard, never rendered — a stage never observed is never shown. Growing the table is a versioned spec amendment, not an ad-hoc string. · `meta-line.ts:112-122` (ADR-0146 F1/F2) · 2026-08-17 · [verified]
16. **Multi-producer orchestration: namespace surface/resource IDs deterministically and classify three ways — own / unprefixed / foreign.** Own ids pass idempotently; unprefixed (model-authored) ids are rewritten onto the namespace — deterministically, so a create and its same-batch populate stay paired; FOREIGN ids (another producer's namespace) are REJECTED outright, never rewritten — a producer must never patch or read a sibling's surfaces. Rewriting only creates (not updates) silently strands same-batch populates as foreign rejects. · `session.ts:110-208` (`enforceSurfacePrefix`, ecosystem SPEC-R4/GH #475) · 2026-08-17 · [verified]
17. **Model-declared routing facts get integrity-checked against what the payload actually did, then silently degrade.** An `ask` naming a surface no payload line creates, or colliding with a session-known surface id, is DROPPED from the outgoing envelope (the prose reply stands, the turn ships) — a wrong routing declaration never halts or retries a turn whose content is valid. Policy violations (out-of-scope component types on the ask surface) instead retry, via produce-layer-only failure codes that never join the protocol's closed error union. · `produce.ts:25-36,704-773` (ADR-0097) · 2026-08-17 · [verified]
18. **The server's validated selection beats client-supplied fields at every trust boundary.** The proxy's allowlist-validated `{provider, model}` takes precedence over any client-supplied `input.model`; likewise the server-selected catalog id is stamped over the model-authored `createSurface.catalogId` after heal, before validate — an unconditional idempotent overwrite, never a heal arm. · `produce.ts:100-105,329-340` (SPEC-R12, ADR-0169) · 2026-08-17 · [verified]
19. **Client-side auto-attach on exact label match closes the "the assistant tells the user to tag something it just offered" UX hole — but keep it exact, one per turn.** After a live incident (dealer persona: "tag @texas-holdem in your next message" one turn after offering the game), the fix resolves a user-typed EXACT label (case/punctuation-normalized) through the same path as an explicit tag. No fuzzy or description matching (false-positive risk explicitly declined); first hit only; never a disabled entry; and the teaching block is re-taught so the model knows naming loads it. · ADR-0190 amendment cl.A1/A2 (GH #1030) · 2026-08-17 · [verified][incident]

## chat-harness-tool-facts

20. **One provider seam, plain fetch, no vendor SDK — enforced by a standing grep gate.** The model seam is a single `AgentProvider.stream()` interface; each adapter is its provider's single SSE→text boundary; a "vendored SDK for friendliness" is "a runtime dependency in costume". The zero-SDK invariant is greppable and gate-enforced daily, not aspirational. · `packages/agent-ui/a2ui/src/agent/agent-transport.ts:126-164` (ADR-0137 cl.8, SPEC-R3) · 2026-08-17 · [verified]
21. **Tool declarations come from a caller-owned registry; the model never invents one; a failed tool degrades the answer, never the turn.** `ToolDef`s are registry-sourced; `executeTool` rejections surface to the model as error-text results; the turn's abort signal threads into in-flight tool work so an aborted turn cancels its tools. · `agent-transport.ts:107-163` (GH #49) · 2026-08-17 · [verified]
22. **Run the provider-native tool loop INSIDE the adapter; the driver's accumulation contract never changes.** The adapter executes calls, feeds results back, and yields only text fragments throughout, bounded by its own round cap — the orchestration loop above it stays provider-agnostic. Lifecycle events ride an optional side CALLBACK (not a union-yielding stream) because there is exactly one caller and the text contract must not change. · `agent-transport.ts:146-163` (ADR-0146 F1) · 2026-08-17 · [verified]
23. **Adapters must degrade a dial they can't map, never forward it blindly.** The seam's contract: an effort/reasoning knob an adapter can't map should be ignored (degraded DIAL), not sent upstream (degraded REQUEST) — the shipped Anthropic adapter's unconditional `thinking` send is documented as latent debt: a future non-thinking model would 400 instead of degrade. · `agent-transport.ts:138-144` (code-review finding, recorded at the seam) · 2026-08-17 · [verified]
24. **Per-tool enablement rots when a server's tool list churns; widen the enablement wire's VOCABULARY, not its shape, with a service reference.** Pinned per-tool ids rot across `tools/list` churn and can't express a 30-tool server under a wire cap. Fix: one grammar member `mcp:<server-id>:*` (anchored whole-string against the server-id charset, so a real tool id ending in `:*` stays individually enablable), expanded SERVER-side against the registry as it stands each turn, fail-closed (no manifests registered ⇒ refs resolve to nothing, inert). Persisting refs in per-agent stores is the reversal cost that made this ADR-worthy. · ADR-0185 (amending four prior pinned fences by version, append-only) · 2026-08-12 · [verified]

## chat-harness-memory-facts

25. **Three-tier capability reach: ever-present · invocable-only · off — two axes (`enabled` × `availability`) never collapsed.** Ever-present entries contribute ambiently every turn; invocable entries contribute ZERO ambient bytes until express invocation; disabled entries are absent from rosters but still LISTED in the menu (a global off-switch you cannot flip back on is not a switch). The persistent switch and the per-turn typeahead are different mechanisms over one store truth — never a second source of truth. · ADR-0190 Decision (Kim's ruling, verbatim in Context) · 2026-08-14 · [verified]
26. **Ambient capability prose is the context-window killer; index lines cut it ~77–80%.** Measured on realistic agents: full-content ambient capability blocks run 10–16 KB (28–45× the persona they ride behind, unbounded in entry count/size); one index line per entry (label + description, 65–102 B vs 218–504 B full) bounds it by count × one line. Full content rides only the express-invocation path. The model is TOLD the index is an index and how entries load. · `capability-availability-tagging.spec.md` §12 byte survey (SPEC-R14/R15) · 2026-08-14 · [verified]
27. **Model-authored memory writes must be non-destructive by construction: partial-record merge law with no deletion semantics.** A persona patch is a model-declared delta: scalar `values` merge last-writer-wins at whole-value granularity (absent key untouched, no deep merge); list `entries` APPEND through the host's validated add path, never replace; no deletes exist in v1 — so a hallucinated patch cannot destroy state. Intent is declared structurally (set vs contribute), never inferred from a key table. · `meta-line.ts:93-109` (ADR-0178/SPEC-R29) · 2026-08-17 · [verified]
28. **The wire layer is gate-blind; the GATE governs consumption and teaching, never framing.** A volunteered patch on a gate-off turn still rides the envelope — what the gate withholds is host-side consumption (a separate three-filter apply step) and the prompt teaching block. Splitting the gate this way leaves zero gate-conditional wire branches to drift. · `produce.ts:167-177,594-600` · 2026-08-17 · [verified]

## chat-harness-guardrail-facts

29. **Every disclosure knob is fail-closed and independent — no accidental ladder.** Progress detail defaults to stage transitions only (no reasoning text); `'full'` (bounded reasoning excerpts, capped ~200 chars) and `'source'` (raw payload lines behind validate/retry stages, capped 16 KB with an EXPLICIT truncation marker — never a silent cut) are separate opt-ins where one never implies the other; a consumer needing both is a deliberate future member, not a ladder accident. · `produce.ts:139-207` (ADR-0146 F3, GH #240/ADR-0159) · 2026-08-17 · [verified]
30. **"A browser cannot hold a secret": the producer runs where the key lives, and dev-key plumbing never ships.** Keys pass into provider factories, never module scope; the local-dev proxy/key-holder stays repo-internal, fenced by a greppable trip-wire (`vite`/`node:http` may NEVER appear in the exported graph). Exporting a producer toolkit means ruling the core/shell cut module-by-module. · ADR-0137 cl.3/cl.8; live layout `packages/agent-ui/a2ui/src/agent/` vs `tools/agent/` · 2026-08-17 · [verified]
31. **A stream whose headers already committed 200 needs a reserved terminal error line, or failures read as empty successes.** Once 200 is committed, a mid-stream halt yields a silently-empty "success" client-side; the fix is a transport-composed terminal `error` meta-line (last line on the stream) that only transports — never the model — may author. Runtime-composed fields (trace, error) and model-authored fields (note, ask, plan) are strictly partitioned by author. · `meta-line.ts:143-157,306-316` (GH #144) · 2026-08-17 · [verified]
32. **Halt loudly at the round bound; a loud halt is a feature.** A model repeating the identical mistake across all retry rounds (observed live at temp 0.9) exhausts the budget and fails closed with named failure codes — trading a possible bad render for a diagnosable error. Never widen the bound to chase a misbehaving model; fix the feedback's teaching instead. · `produce.ts:306-314,381-397` (GH #404, `.claude/ops/mb-live-proof/box2-quizmaster-FAIL.json`) · 2026-08-17 · [verified][incident]
33. **Error text surfaced to end users must contain only ids the model itself emitted, never raw upstream text.** ProduceHalt's `CODE at path` rendering is safe to surface because `path` is always model-authored A2UI ids — a deliberate invariant, documented where the message is built. · `produce.ts:294-314` (GH #307) · 2026-08-17 · [verified]
34. **Additive opt-in flags carry a byte-identical-when-absent guarantee, stated per flag.** Every new knob on the producer/provider seam (mode, effort, progress, tools, genuiSurface, a2uiEnabled…) documents that absence reproduces the prior request/stream byte-for-byte — which is what makes an evolving seam safe for existing consumers and testable by byte-pinned equivalence gates. · `produce.ts:99-189`; `prompt-equivalence.test.ts`, `prompt-drift.test.ts` (`src/live-agent/`) · 2026-08-17 · [verified]

## chat-harness-logging-facts

35. **Assemble the per-turn decision trace at the driver from data already flowing through it — the model never authors its own trace.** `TurnTrace` (retrieval query, exemplar ids, retry rounds, healed-line count, failure codes, model) is runtime-assembled and attached by the loop; a model-authored `trace` is ignored. Observability facts and model output are different provenance classes on one wire. · `meta-line.ts:41-60,143-157` (ADR-0088 §2) · 2026-08-17 · [verified]
36. **Don't let mechanical normalizations saturate your repair metrics.** The healed-line count counts only REAL form repairs, excluding the envelope normalization that fires on every well-formed line — otherwise the metric saturates to line-count on every clean turn and measures nothing. · `produce.ts:554-581` · 2026-08-17 · [verified]
37. **Failure diagnostics must say WHICH member and WHERE, in one format for both audiences.** A halt naming only the code ("IDGRAPH") was undiagnosable live without re-instrumenting; each failure now renders `CODE at path`, the same wording fed back to the model — one format, two audiences (operator + model), so the surfaces never disagree. · `produce.ts:294-314` (GH #307) · 2026-08-17 · [verified][incident]
38. **Progress delivery must be decoupled from the provider's yield cadence.** A provider can run a whole tool round without yielding a text fragment while its event callback fires in real time; draining events only between fragments buffers a round's progress invisibly. Race the iterator's `next()` against a wakeable push channel so events surface the instant they happen, with queued progress always yielded before the fragment that followed it. · `produce.ts:217-279` (GH #290) · 2026-08-17 · [verified][incident]
39. **Byte-pin prompt content with drift gates.** System-prompt and mini-skill texts are file-loaded and equivalence-gated (`prompt-drift`/`prompt-equivalence` tests against a committed baseline) so a refactor that moves prompt files cannot silently change a byte of what the model sees. · `src/live-agent/prompt-drift.test.ts`, `prompt-equivalence.baseline.json` (ADR-0135) · 2026-08-17 · [verified]

## llm-gateway-facts

40. **Single-flight 401 refresh: one in-flight refresh promise shared by all concurrent 401s, with ONE normalized rejection object.** Concurrent 401s dedupe onto one refresh; if it rejects, every queued awaiter receives the same (`Object.is`) typed error — no thundering-herd refreshes, no divergent error objects. · `packages/agent-ui/data/src/gateway/auth.ts:44-56` (SPEC-R9) · 2026-08-17 · [verified]
41. **Replay after refresh with the token the refresh RESOLVED, not a second `getToken()` read** — the getter may lag the refresh; and take the replay-capable clone BEFORE the first send. A second 401 after replay returns as-is: no loop. · `auth.ts:58-75` · 2026-08-17 · [verified]
42. **A one-shot streaming body is honestly unreplayable: reject with a typed error, never tee "just in case".** Detect via a carrier header set at shaping time — testing `body instanceof ReadableStream` is wrong because EVERY bodied `Request` exposes its body as a stream, which would refuse replay for plain JSON. · `auth.ts:14-30,59-68` (SPEC-R9 AC4) · 2026-08-17 · [verified]
43. **Retry defaults: idempotent methods only (GET/HEAD/OPTIONS/PUT/DELETE) or explicit opt-in; full jitter (`random(0, min(cap, base·2^n))`); `Retry-After` overrides when LARGER; the backoff wait is abortable via the request's own signal.** A retryable-but-non-idempotent POST fails after one attempt by design — the caller opts in. · `packages/agent-ui/data/src/gateway/retry.ts` (SPEC-R10) · 2026-08-17 · [verified]
44. **Cancel the body of a response you're about to discard on retry** — cancel is not a read; leaving the stream open holds the connection until GC. And skip cloning entirely when retry cannot happen (single attempt / non-idempotent), plus hand the ORIGINAL request to the last permitted attempt — nothing left to preserve a body for. · `retry.ts:56-99` · 2026-08-17 · [verified]
45. **The streaming pass-through law: NO middleware reads, tees, or buffers `Response.body`.** Retry classifies from status/headers only (a 5xx with a body retries unread); the caller receives `bodyUsed === false`, `body.locked === false` through the whole chain; body-consuming helpers are terminal, never middleware. Enforced with a negative-control test: a planted `await res.text()` inside a middleware must turn the gate RED. · `saas-data-utilities.spec.md` SPEC-R11 + `gateway/passthrough.test.ts` · 2026-08-17 · [verified]

## llm-streaming-facts

46. **ONE streaming contract: `Streamed<T> = AsyncIterable<T>`, with a single push→pull bridge under a DECLARED backpressure policy.** Default is buffer-with-high-water-mark where `push` returns `false` as the producer's cue (never throws) — dropping is a semantic decision an adapter cannot make for the consumer; drop policies exist for telemetry-shaped feeds. `iterator.return()` and `signal.abort()` each end the stream and fire teardown exactly once; push-after-end is a no-op. · `saas-data-utilities.spec.md` SPEC-R12; `data/src/stream/bridge.ts` · 2026-08-17 · [verified]
47. **WebSocket reconnect needs a socket-generation counter: a dying socket's late 'close' event must never re-enter the dead-handler and double-reconnect.** Every listener is bound to the generation it attached under; abandoning a socket (heartbeat death, reconnect, consumer close) bumps the generation, making its late events inert. Abandon = close the dead socket, don't leak it alongside its replacement. · `data/src/stream/from-web-socket.ts:52-138` · 2026-08-17 · [verified]
48. **Heartbeat law: ANY inbound message resets the dead-connection clock (not just pongs); consumer close during the backoff wait wins (no zombie socket); consumer-initiated close is code 1000 and NEVER reconnects** — "finished" and "disconnected" are different stream ends. Reconnect is opt-in with capped full-jitter backoff; exhaustion ends the stream with a typed retryable network error, never a bare Error. · `from-web-socket.ts:101-155` (SPEC-R13c) · 2026-08-17 · [verified]
49. **State EventSource's auth constraint in the export's own docs: no custom headers — cookie or query-ticket auth only; `Last-Event-ID` resume is the platform's.** A grep-gated doc-comment requirement, because every consumer trips on it otherwise. · SPEC-R13b + `data/src/stream/from-event-source.ts` · 2026-08-17 · [verified]
50. **Keep exactly ONE NDJSON line-splitter implementation; old locations become one-line re-exports with identical name and signature**, with the original call-site's chunk-boundary tests re-run against the hoisted body — behavior parity pinned by tests, type parity by the compiler. · SPEC-R13a AC1; `data/src/stream/ndjson-lines.ts` (re-export at `site/lib/ndjson-lines.ts`) · 2026-08-17 · [verified]
51. **Whole-document view transitions and streaming paint are mutually exclusive: never animate first-paint streaming; detect "already painted" with a settled-once boundary.** Wrapping per-streamed-chunk would strobe whole-document snapshots; the event worth a transition is the RE-render of an already-fully-painted surface. The host's first finalize marks it settled; every ingest before that is first-paint (never transitions), every one after is a re-render (may). Also: a validation-stage hook is the wrong grain — the DOM painted progressively before it, so wrapping finalize animates nothing. · ADR-0183 amendment (2026-08-12); wired in `packages/agent-ui/app/src/controls/surface-host/` · 2026-08-17 · [verified]
52. **Coordinated top-down reveal of streamed content trades away stream-liveness — ship it opt-in, default OFF, and name the regression.** Holding an already-arrived later sibling until earlier siblings arrive fixes reveal jitter (components popping at random positions), but a never-arriving earlier sibling then strands every later one — a real regression against "render what is available", accepted only behind the flag; the default path's greedy-reveal tests pass unmodified. Structural resends must resync the order bookkeeping or a removed blocking sibling permanently strands the cursor (caught by review, regression-tested). · ADR-0194; `packages/agent-ui/a2ui/src/renderer/tree.ts` · 2026-08-16 · [verified]
53. **A streaming renderer holds unresolved references as position-preserving anchors and patches them in on arrival — never blocking or erroring on a not-yet-defined reference** — buffering by id decouples arrival order from mount order and is what makes out-of-order streams renderable at all. · `a2ui-runtime.spec.md` SPEC-R4; `renderer/tree.ts` (`#pendingParents`) · 2026-08-17 · [verified]

## agent-residency-facts

54. **Concurrent peer sessions on one repo: the REPO is the coordination channel — claims, PRs, worktrees, and one standing ops file; never another session's transcript.** Peers are separate host processes unreachable by direct messaging; coordination runs through on-issue claim comments (first claim wins, stood-down lanes say so on the record), draft PRs naming their session, and a shared `peer-coordination.md`. Cross-session transcript reads raised a human-facing grant card on EVERY call regardless of bypass mode — root-caused as the day's only grant-raising calls, then banned outright. · `.claude/ops/peer-coordination.md:1-25,81-84` · 2026-08-17 · [verified][incident]
55. **Seats/peers never merge: one host verifies (mergeable + gate evidence + findings write-back) and merges SERIALLY, re-running the full gate on main between merges, judged by exit codes only.** Dispatched subagent sessions get push/PR-create denied by the harness; they commit + draft, the host ships. · `peer-coordination.md:15-18`; memory `subagent-ship-leg-classifier-block` · 2026-08-17 · [verified]
56. **Red gates on a loaded multi-agent host are not evidence: isolate before believing.** Measured instance: load 30–52 with concurrent sessions produced three NON-overlapping failing test sets, all green in isolation; the standing rule is foreground gates, staggered full-suite runs, and per-file isolation as the reliable verdict. Bonus trap: a `ps`-based "is the suite still running" check matches its own wait-loop pattern. · `peer-coordination.md:20-24,37-40` · 2026-08-15 · [verified][incident]
57. **Hooks are a SEPARATE enforcement layer from the permission system — bypassPermissions does not silence a PreToolUse hook, and an enabled plugin's hooks fire session-wide, not just for that plugin's agents.** An overnight run kept prompting despite bypass mode; root cause was a plugin's ask-first Bash hook, not permission prompts. Also: plugin dirs are fixed at process spawn — already-running subagents are unaffected by a mid-run plugin disable, but new dispatches against its agent types stop resolving. · `peer-coordination.md:105-117` (Kim, 2026-08-17) · 2026-08-17 · [verified][incident]
