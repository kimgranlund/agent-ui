# Descriptor generation — the `{name}.md` → `{name}.props.gen.ts` inversion

Ground truth: `packages/agent-ui/components/src/descriptor/component-descriptor.ts` (the one
parser/schema/trip-wire module — never a second frontmatter reader, ADR-0173 cl.3), the generator
module it drives, and `packages/agent-ui/icons/src/phosphor/icons.gen.ts` (the committed-generated-
file vehicle this pattern reuses, ADR-0066). Decision record: ADR-0173.

## The rule: descriptor is SOURCE for props, never for the catalog row

**Props layer — generated.** A control's `{name}.md` descriptor is the generation SOURCE for its
`static props` table (and, via `ReactiveProps<typeof props>`, its type layer) — not a hand mirror
held honest by a trip-wire. Behavior source (`.ts` bodies, `.css`) and the descriptor's own prose
sections stay hand-authored forever; s11 (`compareDescriptorToSource`) stays a trip-wire permanently
because it guards facts (`customStates`, `slots` positioning) no `static props` row carries at all
(ADR-0173 cl.1, cl.4d).

**Catalog row — never generated, ruled out, not merely deferred.** `@agent-ui/a2ui`'s catalog row
is curated wire-contract content (renames, controller-owned actions, deliberate prop omissions) with
no descriptor analogue, sits across the `components → a2ui` package-ownership boundary, and two of
three catalog shapes (`a2ui-basic`'s upstream-pinned schema, M-D's compose-time-derived personas)
cannot participate at all (ADR-0173 cl.5). A future ADR would have to supersede cl.5 explicitly to
reopen this — don't propose catalog-row generation without one.

## The committed sibling: `{name}.props.gen.ts`

Generation writes a separate, committed file per control — never an in-place marked-region rewrite
of the hand-authored `{name}.ts` (rejected in ADR-0173 cl.3 as a corruption risk with no offsetting
benefit; a separate file gives the drift gate a whole-artifact diff target). The vehicle is the
`icons.gen.ts` shape (ADR-0066): generated, committed, regenerated by an npm script, never hand-edited.
`{name}.ts` drops its hand table and imports `props` from the sibling; `static props = props` is
unchanged.

## The `attributes[]` grammar additions (ADR-0173 cl.2, amended)

Five fields promoted from comments/nothing into the s9-validated grammar, each legal only in its
own context:

| Field | Legal when | Carries |
|---|---|---|
| `attribute` | any attribute row (absent ⇒ derived from prop name) | string \| `false` — the DOM attribute name override, or opt-out |
| `tsType` | `type: json` | a TS type expression string (e.g. `number[] \| undefined`) |
| `const` | `type: enum` | the exported shared-tuple constant's name (e.g. `PLACEMENTS`) |
| `codec` | a bespoke, hand-rolled `PropConfig` (the 7-control allowlist below) | `{ import: '<sibling-relative path>', name: '<exported identifier>' }` — the generator imports it BY NAME and splices it in, never reparsing `type`/`default` for that row |
| `description` | any attribute row | plain scalar, emitted as a provenance-stamped comment above the generated field |

`default` stays the existing string field, reparsed by declared kind at generation time — no new
field needed for defaults.

## The 7-control bespoke-codec allowlist (seed population, drains via `codec:`)

`table`, `bar-chart`, `sparkline`, `stat`, `sandbox-frame`, `ladder`, `ramp` — each has at least one
hand-rolled `PropConfig` encoding real parse/sanitize logic (`safeJsonCodec`, `barDataType`,
`tokenEntriesType`, …) a bare `prop.*()` factory call cannot express. They are NOT permanently
excluded: the `codec:` field (ADR-0173's OF1 resolution) lets them generate too, by importing the
control's own already-assembled `PropConfig` instead of synthesizing one. A control leaves the
allowlist when its `attributes[]` rows carry `codec:` and its generated sibling lands — check the
live allowlist file at migration time, this list is the ratification-time seed, not a standing
count.

## The drift-gate pattern: same generator, diffed against committed output

The gate that replaces (never merely supplements) the old `compareDescriptorToProps` trip-wire is
the SAME implementation the build script runs, regenerating each converted control's props module
in-memory from its descriptor and diffing against the committed `{name}.props.gen.ts` (the
`llms.test.ts` G1 pattern, reused exactly). This catches both directions of drift a hand-authored
mirror couldn't: a descriptor edited without regeneration, AND a hand-edited generated file (legal
before generation existed, a red gate now).

A second, independent gate — `a2ui/src/catalog/default/descriptor-agreement.test.ts` — checks catalog
`PropDef`s that `mapsTo` a descriptor attribute agree on type kind + enum members; it is NOT a
generation gate (catalog rows never generate, above) — it closes the one drift class the catalog
side lacked, on the ADR-0087 include-or-recorded-exclusion shape (deliberate narrowings get a cited
exception-table row, not a failing test).

## s10-retires-per-control / s11-never — the sequencing law

- **s10** (`compareDescriptorToProps`, the old contract↔props bijection trip-wire) retires **in the
  same commit** that lands a control's generator-drift-gate coverage — never a commit where both
  exist for that control, never one where neither does. This is a literal commit-sequencing
  discipline (ADR-0173 Amendment, OF4 resolved), not a background cleanup task.
- **s11** (`compareDescriptorToSource`) **never retires**, for any control, ever. Its ground truths
  (`customStates`, `slots` CSS positioning) are facts the descriptor states but the `static props`
  block structurally cannot carry — converting it would mean generating behavior from docs, which
  this architecture does not do and does not want.

## Applying this to a new or converting control

1. Check whether the control needs a `codec:` row (does any prop use a hand-rolled `PropConfig`
   beyond a bare `prop.*()` factory call?). If yes, the descriptor's `attributes[]` row for that
   attribute carries `codec:`, not `tsType`/`const`.
2. Every `json`-typed attribute needs `tsType`; every `enum`-typed attribute built from a shared
   tuple needs `const`. A descriptor that's s9-schema-valid can still be generation-UNGENERATABLE
   (missing `tsType`/`const`/`codec`) — that's its own coded failure class (`GEN_TYPE_UNRESOLVED` /
   `GEN_CONST_UNRESOLVED`), never a silent partial emit.
3. Land the generated `{name}.props.gen.ts`, repoint `{name}.ts`'s import, and retire that control's
   s10 assertions in the SAME commit.
4. Never touch the catalog row as part of a props-generation conversion — that's a structurally
   separate decision (above), and the agreement gate, not this conversion, is what would flag it if
   it drifted.

See ADR-0173 (and its 2026-08-06 Amendment resolving OF1–OF4) for the full argument and the first
build wave's real conversions (`ui-button`, `ui-table`, `ui-badge`, `ui-avatar`, `ui-progress`).
