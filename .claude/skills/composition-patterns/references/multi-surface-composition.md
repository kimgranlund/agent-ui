# Multi-surface & composition-authority patterns

What happens when more than one live surface/composer/pane shares a page — origin-keyed
composer routing, the shown-set/primary multi-pane visibility model, band-driven docking,
retracting a painted affordance without losing its semantics, the mint-vs-compose test, and
declarative chat composition. Read this file when two or more composed surfaces interact, or
when deciding whether a pattern needs a new fleet primitive.

| Assembly problem | The fleet's answer | Owner · exemplar |
|---|---|---|
| Two live conversations (two composers) on one surface, each driving its own store | route each submitted turn by the SUBMITTING COMPOSER's ORIGIN — each composer permanently IS a context; pane/nav selection state is only a proxy for it and breaks the moment two composers are typable at once (the cross-route defect was reproduced as a negative control before the re-key). Origin stays the element's routing business, never a member of the runner's wire shape | ADR-0179 first Amendment (the cl.2 ORIGIN re-key, GH #662) · `packages/agent-ui/app/src/controls/agent-admin/agent-admin.ts` (`#contextFor`) |
| Multi-pane visibility that must survive wide⇄narrow crossings | ONE state, two renderings — never two state machines: a shown-SET (wide truth, min-one invariant — the last-on toggle is refused) plus a primary member (narrow truth); wide multi-select pills write membership, the narrow single-select segment writes primary. The apply method writes `data-show` + `data-primary` onto the holder and nothing else; a resize writes NOTHING, so band crossings project and restore losslessly | ADR-0179 GH #686 Amendment (the visibility model) · `agent-admin.ts` (`#setPanesShown`) + `agent-admin.css` (the pane-holder sheet) |
| "At which width do panes dock side by side?" | the SHEET decides what paints, reading the holder's own inline-size against the shell family's NAMED band ladder (`SHELL_NARROW_BREAKPOINT` / `SHELL_COMPACT_BREAKPOINT`) — never a new magic number, and one named line serves every swap that must move together (the header rendering and the pane arrangement share it, or the header could promise what the surface can't paint) | ADR-0150/0155 (the ladder) + ADR-0179 GH #686 Amendment (the reuse rationale) · `packages/agent-ui/app/src/shell-breakpoint.ts` (+ its literal-drift gate, `shell-breakpoint.test.ts`) |
| A composed control's painted affordance is unwanted, but its semantics must survive (e.g. dividers between docked regions) | RETRACT, don't delete — repoint the control's own token locally (`--ui-split-divider-ink: transparent` on the `ui-split` elements THEMSELVES; a locally-declared custom property beats an inherited one regardless of ancestor specificity): the separator element, its hit-slop, `role=separator`, tabindex, keyboard step and drag all survive; only the resting ink goes, and the hover/drag cue stays painted so the handle still answers a reach | ADR-0179 first Amendment (no-painted-dividers, GH #662 Findings) · `agent-admin.css` (the repoint block) + `controls/split/split.css` (the token's owning declaration) |
| The surface needs a control no shipped `ui-*` semantically matches | the mint-vs-compose test: mint a new fleet primitive ONLY when no shipped control's SEMANTICS fit — never bespoke-state a composed control (the second consumer re-mints it) and never fork a shipped control's semantics with a flag (`ui-segmented-control` + `multiple` was rejected: radio inheritance makes that a semantics fork). Exemplar: `ui-toggle`, minted because `ui-switch` is a track-and-thumb form control, the segmented control is single-select by construction, and `ui-button` carries no pressed state. Route the mint through [[component-design]] | ADR-0179 GH #686 Amendment (the `ui-toggle` ruling) · `packages/agent-ui/components/src/controls/toggle/` |
| Authoring a chat surface's parts declaratively instead of driving the imperative API | the OPT-IN recognized-children contract: author `:scope >` `ui-conversation-header` / `-dialog` / `-composer` children and `<ui-conversation>` ADOPTS them at connect; no children means the byte-identical imperative default. The header is the family's one fully author-composed member (its children are your DOM); the adopted dialog/composer stay engine-driven — you author placement, never a second API (producer mechanics: [[component-patterns]]) | ADR-0180 + `app-surfaces-m2.spec.md` SPEC-R13 · `packages/agent-ui/app/src/controls/conversation/` |
