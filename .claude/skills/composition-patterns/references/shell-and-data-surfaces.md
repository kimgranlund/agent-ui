# App-shell, navigation & data surfaces

Cross-view navigation, the application-shell region contract, and the schema/store-driven
data-management surfaces (settings, resource lists, table toolbars, record-CRUD). Read this
file when wiring a shell region, a settings/config page, a resource-list manager, a data-table
toolbar, a record open/validate/save loop, or a card-grid view with an edge-docked drawer edit flow.

| Assembly problem | The fleet's answer | Owner · exemplar |
|---|---|---|
| Navigation between views | memory-first routing: `createRouter`/`connectUrl` (headless core) + `ui-router-outlet`/`ui-router-link` on their own subpaths — URL reflection is opt-in; a2ui surfaces never see the router (catalog-invisible by construction) | ADR-0115 · `packages/agent-ui/router/` |
| Regions of an application shell | ONE `ui-super-shell`, no region sub-element — children carry `data-slot="header\|global-nav\|nav-pane\|section-nav\|content\|options-section\|options-pane\|global-options\|footer"`; per-side `collapsed-*`/`narrow-*`/`collapse-band` own the responsive story. Reach for the `ui-workspace-shell`/`ui-chat-shell` presets when the archetype fits | ADR-0151/0154/0155 (ADR-0156 removed the older `ui-app-shell`) · `packages/agent-ui/app/` |
| A schema-driven settings/config page | `ui-settings` + `SettingsSchema` + a `SettingsStore` — the fold-column variant rides `ui-disclosure` + `slot="summary"` master switches | ADR-0120/ADR-0158 · `packages/agent-ui/app/src/controls/agent-admin/agent-admin.ts`'s `settingsItem` helper (a thin wrapper over `foldItem`/`ui-disclosure`, GH #225) |
| A resource-list manager | `./entry-list` (`@agent-ui/app`'s `mountEntryList`) + the live-apply store discipline — commit on `change` (never `input`) → `store.set` → `subscribe` re-render (focus-preserving) → fresh store read at consume time, no push channel | ADR-0132/ADR-0164 · `packages/agent-ui/app/src/controls/agent-admin/agent-admin.ts`'s `#makeSection` |
| A data-table toolbar drives `ui-table`'s own state, never its rows | search rides a `ui-text-field` bound one-way to the table's `search` prop; facets ride `ui-form-popover` + a `ui-checkbox` group in its panel, the page aggregating the checked set into ONE `{key, values[]}` `filter` entry — the toolbar only ever sets `table.search`/`table.filter`, so the bound `rows` array's identity never changes across a filter interaction | ADR-0163 cl.2/cl.7 (filter/search state + the view pipeline order) + PRD-D3/SPEC-R7 (the popover-vehicle ruling) · `site/pages/workbench.ts` (the toolbar composition — `updateStatusFilter`) |
| A record-CRUD loop: open → validate → save/cancel over one record | a persistent, keyboard-focusable `ui-button` OUTSIDE the table's stamped anatomy opens a `ui-modal` hosting `ui-form-provider` + `ui-field`-wrapped FACE controls over the record's scalar fields; save calls `provider.submit()` (blocks on invalid, no store write), commits through the extracted store discipline, and on close focus restores to the opener while the matching table row updates in place | ADR-0120/ADR-0158 (the store precedent) + PRD-D6/SPEC-R8 (the `ui-modal`-over-`ui-master-detail` ruling) · `site/pages/workbench.ts` (the record-edit flow — `openEditModal`/`saveButton`) |
| Column show/hide + reorder over `ui-table`, with ZERO `ui-table` API change | a `ui-form-popover` "Columns" menu (never `ui-menu` — same close-on-every-commit disqualifier PRD-D3 already ruled for the status facet) holds one row per column: a `ui-checkbox` (visibility) + move-up/move-down `ui-button`s (order); the page reduces its own `columnOrder`/`hiddenColumnKeys` state into ONE `table.columns` write per change — `columns`' existing order-is-render-order / omission-is-hidden seam (table.md) needs no control change at all. Per-user persistence of the layout is a separate, open seam (GH #959, awaiting a ruling) — this recipe's own state is page-local and resets on reload; in-header drag-reorder and edge-drag resize stay fenced to a later ADR | GH #963 · `site/pages/workbench.ts` (the columns-menu composition — `applyColumnsState`/`renderColumnsList`) |
| Card-arranged entity views with an edge-docked drawer edit flow (dirty-state guard, write-back, danger action) | `ui-grid` of `ui-card`s, each Edit opening the SAME `ui-drawer` an "Add" affordance does (entry-form.ts's GH #917 two-mode-one-form shape); the form BUFFERS every field until Save commits it to the store (never per-field-on-change) — a plain snapshot taken at open + a `dirty` signal recomputed on `input` REFLECTS onto `drawer.persistent`, so Escape/backdrop are inert while dirty and the footer's own Cancel becomes a one-shot "Discard changes?" confirm. `open`/`editingId` are two SEPARATE signals (ADR-0019's two-way `open` binding done by hand: the platform's own `close` event writes back). The dirty-guard is a RECIPE-level convention, not a fleet ADR (pre-decided, ops plan §3.3) — `ui-drawer` itself ships no dirty-tracking | SaaS UX brief §6 (`saas-ux-flows.brief.md`) + GH #917/#947 (PR #948, the agent-admin entry-list/entry-form precedent) + #949/#950 (PRs #987/#997 — persistent-while-dirty replaces #950's per-kind draft buffer because the buffered form never lets a dismiss land silently) · `site/pages/card-grid-drawer.ts` (GH #965) |
| A long-form corpus's sticky TOC, collapsing to a `select` on mobile | a scroll-spy'd `ui-nav-rail` (`collapse="none"`, link-shaped `href="#slug"` items, heading-derived — never a hand-authored parallel list) swapped to a `ui-select` below the ADR-0150 compact line, via the SAME `data-compact`/`ResizeObserver` idiom `ui-settings`' rail→select swap uses (GH #962); the new `scrollSpy` IntersectionObserver trait (`@agent-ui/components/traits/scroll-spy`) drives BOTH halves' active-state in lock-step from one call. Mint-last verdict: no `ui-toc` — the composition carries the whole pattern in ~150 lines over shipped controls | GH #964 · `packages/agent-ui/components/src/traits/scroll-spy.ts` + `site/pages/toc-content.ts` |
