# Composition patterns — the consumer assembly map

How a page correctly *consumes* the fleet. Each row: the assembly problem → the fleet's
answer → the owner (rationale) and the worked exemplar (live code). The mechanism stays in
the owner; deviating from a row on a shared surface is a fork, not a local choice.

| Assembly problem | The fleet's answer | Owner · exemplar |
|---|---|---|
| A labelled, validated form | `ui-form-provider` (the registry) + `ui-field` wrapping each control (the labelling seam; error rendering is reactive and field-owned) — never hand-rolled `<label for>` plumbing | ADR-0050/0051 · `site/pages/forms.ts` (one live form the whole guide narrates) |
| Spacing inside cards/modals/panels | the `[data-box]` container box-model owns region padding and content gaps — CONSUME it; adding your own padding inside a boxed region double-pads | ADR-0046 · `packages/agent-ui/components/src/controls/_surface/container-box.css` |
| Opening/closing an overlay from page code | the overlay-bearing control's **prop is the source of truth** — flip the prop (`open = !open`), never poke a platform handle (`.showPopover()`/`handle.toggle()`) under the control | ADR-0101 (the model-driven open/close loop) + ADR-0045 (platform-owned dismissal) · `packages/agent-ui/components/src/controls/select/`, `…/controls/menu/` |
| Page styling around controls | a control must work with ZERO consumer CSS (ADR-0102) — so a page never NEEDS to restyle `ui-*` internals; element-level overrides remain a page freedom (ADR-0102 keeps them), but the docs-site discipline is never to use it (states/appearance belong to the control's own CSS), and a visual defect routes down the lanes BEFORE any page CSS lands | ADR-0102 · the docs site's own pages (any `site/pages/*.css`) |
| "Where does the page scroll?" | ONE owned scroll region per surface — the site shell's is `.app-page` (`site/pages/_page.css`; the document never overflows); scroll-into-view code must target the real scroller, deferred past layout settle | TKT-0004's findings · `site/pages/a2a-artifact-feed.ts` (`revealScroll`) |
| Theming a subtree (dark panel in a light app) | wrap in `ui-theme-provider` — `scheme` re-roots `color-scheme`; UNSET means inherit-ambient; remember `color` does NOT re-root with it (the ink re-root lesson: re-declare text color where a scheme boundary starts) | ADR-0117 · `packages/agent-ui/components/src/controls/theme-provider/` + `site/lib/component-gallery.css` (the ink re-root rule) |
| Sizing a region's controls together | the `[scale]` tier attribute (ui-sm…content-lg) and `[density]` (compact/comfortable/spacious) cascade over subtrees — set them on containers, not per-control | ADR-0032/0038 (the law is [[agent-ui-component-standards]]'s territory) · `site/pages/sizing.ts` |
| Scheme-divergence expectations | some color roles are deliberately scheme-INVARIANT (`--md-sys-color-primary` identical both branches) — check the role's two `light-dark()` branches before expecting a dark/light difference | `@agent-ui/shared` tokens.css · `site/lib/theme-provider-build.browser.test.ts` (its probe comments name the invariant) |
| Navigation between views | memory-first routing: `createRouter`/`connectUrl` (headless core) + `ui-router-outlet`/`ui-router-link` on their own subpaths — URL reflection is opt-in; a2ui surfaces never see the router (catalog-invisible by construction) | ADR-0115 · `packages/agent-ui/router/` |
| Regions of an application shell | ONE `ui-super-shell`, no region sub-element — children carry `data-slot="header\|global-nav\|nav-pane\|section-nav\|content\|options-section\|options-pane\|global-options\|footer"`; per-side `collapsed-*`/`narrow-*`/`collapse-band` own the responsive story. Reach for the `ui-workspace-shell`/`ui-chat-shell` presets when the archetype fits | ADR-0151/0154/0155 (ADR-0156 removed the older `ui-app-shell`) · `packages/agent-ui/app/` |
| A schema-driven settings/config page | `ui-settings` + `SettingsSchema` + a `SettingsStore` — the fold-column variant rides `ui-disclosure` + `slot="summary"` master switches | ADR-0120/ADR-0158 · `packages/agent-ui/app/src/controls/agent-admin/agent-admin.ts`'s `settingsItem` helper (a thin wrapper over `foldItem`/`ui-disclosure`, GH #225) |
| A resource-list manager | `./entry-list` (`@agent-ui/app`'s `mountEntryList`) + the live-apply store discipline — commit on `change` (never `input`) → `store.set` → `subscribe` re-render (focus-preserving) → fresh store read at consume time, no push channel | ADR-0132/ADR-0164 · `packages/agent-ui/app/src/controls/agent-admin/agent-admin.ts`'s `#makeSection` |
| A data-table toolbar drives `ui-table`'s own state, never its rows | search rides a `ui-text-field` bound one-way to the table's `search` prop; facets ride `ui-form-popover` + a `ui-checkbox` group in its panel, the page aggregating the checked set into ONE `{key, values[]}` `filter` entry — the toolbar only ever sets `table.search`/`table.filter`, so the bound `rows` array's identity never changes across a filter interaction | ADR-0163 cl.2/cl.7 (filter/search state + the view pipeline order) + PRD-D3/SPEC-R7 (the popover-vehicle ruling) · `site/pages/workbench.ts` (the toolbar composition — `updateStatusFilter`) |
| A record-CRUD loop: open → validate → save/cancel over one record | a persistent, keyboard-focusable `ui-button` OUTSIDE the table's stamped anatomy opens a `ui-modal` hosting `ui-form-provider` + `ui-field`-wrapped FACE controls over the record's scalar fields; save calls `provider.submit()` (blocks on invalid, no store write), commits through the extracted store discipline, and on close focus restores to the opener while the matching table row updates in place | ADR-0120/ADR-0158 (the store precedent) + PRD-D6/SPEC-R8 (the `ui-modal`-over-`ui-master-detail` ruling) · `site/pages/workbench.ts` (the record-edit flow — `openEditModal`/`saveButton`) |
| A credential form (registration or sign-in) | the same `ui-form-provider` + `ui-field`-wrapped-control spine as the "labelled, validated form" row above, over ONE shared auth-card shell — a server-side rejection (an unhappy-path error CODE from the injected transport seam) and a cross-field check (confirm-password) both still call `setCustomValidity()` on the offending field (correct and load-bearing: `provider.submit()`'s own gate reads the MERGED validity, so a poisoned field genuinely blocks a premature resubmit), but a PURELY custom message (no matching native constraint) never renders through `ui-field`'s own inline error part — `ui-text-field`'s `formUserInvalid()` gate is blind to a custom-only message (`text-field.ts`'s `trackUserInvalid` wiring reads only the native `formValidity()` verdict; a live-browser-gate finding, not a style choice) — so the message rides a page-owned status caption instead, the channel proven to actually reach the user | ADR-0176 cl.1/cl.2 (Lane C, the demo-only security fence) + `identity-mock-transport.spec.md` SPEC-R1/R5/R8/R9 (the injected-seam contract + its DEV-only fence) · `site/pages/credentials.ts` (the sign-up/sign-in pair — `wireRegister`/`wireSignIn`, see its own file banner for the finding) |
| A credential-less sign-in (magic link) | request → a "check your email" confirmation state (`ui-text` + a page-level, non-field-shaped resend affordance — a disabled `ui-button` driving a plain interval-updated countdown, `setInterval`/signal state, not a new control capability) → confirm. Unlike the credential-form row above, the confirm step's rejections (an expired/invalid link from the transport seam) attach to NO form field at all — it is a stateless affordance click, never a `provider.submit()`-gated resubmit — so there is nothing to `setCustomValidity()` and the fixed GH #554 gap never arises here; the message rides the SAME page-owned status caption the credential-form row uses, straight, no field-poisoning needed | ADR-0176 cl.1/cl.2 (Lane C, no new control) + `identity-mock-transport.spec.md` SPEC-R3/R5/R8/R9 · `site/pages/magic-link.ts` (`wireMagicLink`, see its own file banner for the no-field-rejection finding) |
| A segmented one-time-code sign-in (OTP) | request → `ui-otp-field` (GH #490 S2-a, the family's one Lane-A control) field-wrapped like any other entry control → signed-in. NO submit button: the control's own `change` event — fired ONLY on a real user-driven completion, never a programmatic value/length write (code-entry-control.lld.md §8) — IS the verify trigger; resend rides a REAL, server-enforced per-email cooldown (identity-mock-transport.spec.md SPEC-R2 AC4), mirrored client-side, unlike the magic-link row's page-only countdown. Unlike the credential-form row's own workaround, `code-invalid`/`code-expired` DO render straight through `ui-field`'s inline error via `setCustomValidity()` — `ui-otp-field` was built AFTER the fixed GH #554 `mergedValidity()` path landed fleet-wide, so no page-owned status-caption duplicate is needed for those two. `code-rate-limited` (reachable from a resend click AND from a sign-out → fast re-request — the transport's per-email cooldown state outlives a sign-out) is not "this input is wrong," so it rides the status caption instead | ADR-0176 cl.1/cl.2 (Lane C composition over the one Lane-A control) + `code-entry-control.lld.md` (`ui-otp-field`) + `identity-mock-transport.spec.md` SPEC-R2/R5/R8/R9 · `site/pages/otp-signin.ts` (`wireOtpFlow`, see its own file banner for the completion-change trigger + the #554-fixed-path finding) |
| A social provider sign-in (redirect + callback) | a provider-button row over plain `ui-button` — no form, no field, no `ui-form-provider` (there is no input to validate at all) — where `startSocialSignIn` IS the simulated redirect (its `redirectHint` is DISPLAY-only, never a navigation-sink assignment, SPEC-N8) and the callback card's two actions ARE the simulated OAuth callback: "Complete" calls `completeSocialSignIn` for the started provider, "Cancel" calls it with the seam's own `provider: 'generic'` sentinel (SPEC-R4 AC4's named "demo-denial affordance") regardless of which real provider was started — OQ2's ruling (2026-08-07: GENERIC, not real brand marks) is realized here as NO icons at all, the most generic option, text-labelled buttons only | ADR-0176 cl.1/cl.2 (Lane C, no new control) + `identity-mock-transport.spec.md` SPEC-R4/R5/R8/R9 · `site/pages/social-signin.ts` (`wireSocialSignIn`, see its own file banner for the redirect/callback simulation) |
| A stepped onboarding flow (first-run) | next/back/skip navigation over plain `ui-button` + page-level signal-driven step-panel switching — "the same shape any multi-view page already uses; no new interactive control required" (ADR-0176 cl.1's own Onboarding ruling) — paired with the `ui-progress` `segments` prop (OQ1's 2026-08-07 "build it" ruling) for a literal discrete "Step N of M" readout (`<ui-progress current="2" segments="4" label="…">`), never the continuous `current`/`max` approximation. The whole journey gates on `getSession()` alone (identity-mock-transport.spec.md SPEC-N7 — Onboarding earns NO new transport operation over S1's `signInWithPassword`/SPEC-R5); a standalone docs-site page with no real "arrived from Authentication" hop simulates that with a one-click "Simulate a completed sign-in" against the SPEC-R6 seeded demo account. Skip (any step) and Finish (the last step) both reach the SAME terminal state — a different PATH there, never a different outcome | ADR-0176 cl.1/cl.2 (Lane C, Onboarding ruling) + `feed-family.spec.md` SPEC-R1 Amendment v1 (`ui-progress` segments) + `identity-mock-transport.spec.md` SPEC-N7/R5 · `site/pages/onboarding.ts` (`wireOnboarding`/`renderStep`, see its own file banner for the SPEC-N7 gating + step-content design) |

## The one law under all of it

**The CSS-less consumer** (ADR-0102): every shipped control must be fully functional and
presentable with zero consumer CSS. If a composed surface looks broken, route the bug down
ADR-0102's three lanes — component-owned defect · catalog-reachable prop gap · taught idiom
(the page held it wrong) — before writing page CSS over it (the ADR states the lanes as
contract-authoring rules; the diagnostic use is this map's recast). Visual proof: the
ADR-0110 screenshot harness (Chromium committed baselines, opt-in `*.visual` suites) plus
computed-style probes as WebKit's sanctioned leg.
