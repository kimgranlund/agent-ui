4. Check arm, `checks.ts` (ADR-0243: the two hands must be `{path}` bindings to `/dealerHand` and `/playerHand`, totals computed from them):
   - Each `CardTable` component adds one hand container per participant from its `dealerHand`/`playerHand` prop; the participant comes from the prop name, never the id. An absolute `{path}` reads the list from the data model (rendered = list length, zero for a non-array); a literal array gives its items. Read a card from a list item's own `rank`/`faceDown` (a new item reader; `cardOf` reads component props and does not apply). A relative path or a function call is indeterminate: no container, no finding.
   - New code `HAND_BINDING` (codes are free upper-snake strings, `catalog/semantic-check.ts:17,44`): fires when a CardTable hand is a literal list, or a `{path}` other than `/dealerHand` (resp. `/playerHand`). Path `<surfaceId>:<CardTable id>`; the message tells the model to write the cards at `/<p>Hand` and bind `"<p>Hand":{"path":"/<p>Hand"}` so a draw appends to the list.
   - The CardTable's `dealerTotal`/`playerTotal` props are readouts for that participant, labelled `<id>.<p>Total`, skipped when bound to `/<p>Total` or `/<p>/total` (judged once at the path, as `checks.ts:169` already does for a component readout).
   - A HAND_COUNT finding on a CardTable container tells the model to bind `<p>Hand` to the listed path (the current message names a Row template, which does not apply). NATURAL_ACTIONS and the one-container-per-participant rule apply unchanged. Update the header comment.
