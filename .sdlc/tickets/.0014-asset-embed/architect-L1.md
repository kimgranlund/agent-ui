## Approach

The five modules the `./agent` subpath admits `node:fs` into (`system-prompt.ts`, `mini-skills.ts`, `prompts/genui-packs.ts`, `selection-guidance.ts`, `dogfood-inventory.ts`; the `NODE_ALLOWED` set at `gates.test.ts:108`) all read repo paths off `process.cwd()`. That one mechanic is why three runtimes each need a workaround: the dev proxy must avoid `import.meta.url` (the vite-temp trap, TKT-0044), the Worker aliases `node:fs` to a hand-listed shim (`wrangler.jsonc` `alias` + `fs-shim-content.ts` FILES/DIRS, 151 lines, gated by `fs-shim.test.ts`), and npm drops `./agent` (`publish-packages.mjs:96`). The vehicle is forced, not chosen: `?raw` passes through tsc verbatim (publish header lines 31-33), `import.meta.glob` is Vite-only, the Worker bundles with esbuild. The only carrier all three share is a committed, generated TypeScript module holding each asset as a string constant. So the design is: generate once, read from the module everywhere, delete the shim.

One generator, `scripts/generate-agent-assets.mjs`, discovers by rule (never by list): every `*.md` under `src/agent/prompts/**`, every `selection.json` under `src/catalog/**` (persona fragments included, `fixture-demo` too), and every `controls/*/` folder's descriptors plus its `.define('ui-…')` call sites. It emits two committed files under `packages/agent-ui/a2ui/src/agent/`: `assets.gen.ts` (`AGENT_ASSETS`, keyed by src-relative POSIX path, each value `JSON.stringify`'d with no normalization, about 97 KB) and `dogfood-fleet.gen.ts` (`DOGFOOD_FLEET`, derived rows `{tag, summary, attrs, siblings}`; raw descriptors are 1.1 MB across 82 files and cannot be embedded). A ten-line `asset-source.ts` (`readAsset`, `listAssets`, fail-loud on an unknown key, the fs-shim's own rule) replaces `readFileSync`/`readdirSync`/`statSync` in the loaders; `process.cwd()` and `declare const process` disappear from all five. Byte identity with the golden baseline holds by construction: the loaders keep their `.trim()`, the emitter never touches line endings. A freshness test regenerates in memory and byte-compares (the `build-dogfood-assets.mjs` / `dogfood-assets-freshness.test.ts` precedent: one write-free function shared by CLI and gate), and `check:scripts` gains `generate-agent-assets.mjs --check` (the #1814 `generate-controls.mjs --check` shape). The generator resolves from `process.cwd()`, not `import.meta.url`, because the freshness test runs in the jsdom `packages` project where `import.meta.url` is not a `file:` URL (`build-dogfood-assets.mjs:28-34`).

With no module in the exported graph importing `node:*`, the Worker's `fs-shim.ts`, `fs-shim-content.ts`, `fs-shim.test.ts`, `process-shim.ts`, the `alias` block and the `*.md` Text glob all go (the `*.jsonl` glob stays for `worker/index.ts:49`'s corpus shard); the NODE-FENCE tightens to zero; `EXCLUDE_EXPORTS_FROM_PUBLISH` loses its only entry and `./agent` ships. This supersedes ADR-0137 cl.4 ("EXACTLY TWO modules" admit `node:fs`; "node-first") in part, so it earns a new proposed ADR, numbered after ADR-0233 lands. A code-read finding rides along: `dogfood: true` from `site/pages/gen-ui-live.ts:112` reaches the deployed Worker (`worker/index.ts:254,297` forwards `genuiSurface`; `system-prompt.ts:331-333` calls `dogfoodInventory()`), which `readdirSync`s `/packages/agent-ui/components/src/controls`, a key `fs-shim-content.ts` never had; GH #811 fixed the build-time `statSync` export only, and `gh issue list --search` on "dogfood worker" and "fs-shim" shows the runtime arm unfiled. The design closes it.

The Kim fork, recorded here, is where the dogfood fleet snapshot lives. Recommended and encoded in the manifest: a2ui-owned derived rows, which deletes the shim entirely and makes `./agent` honestly publishable, at the cost that a descriptor edit in `components` now reds an a2ui freshness gate until someone runs the generator (same cadence `*.props.gen.ts` already imposes). Arm two: the same rows generated inside `components` and imported by a2ui, which keeps regeneration in the package that changed but puts teaching-shaped prompt data in the framework package. Arm three: leave dogfood out of scope, which keeps the shim, the alias and the process shim alive for one module and ships `./agent` with a call-time `node:fs` throw behind `dogfood: true`.

## Constraints and assumptions

- A generated `.ts` string module is the only asset carrier that survives tsc emit, esbuild (wrangler) and the vite-temp dev-proxy bundle: verified by `publish-packages.mjs:31-33` (`?raw` passes through tsc), `wrangler.jsonc` `rules` (esbuild Text loader), `system-prompt.ts:59-65` (vite-temp relocation).
- Emitting via `JSON.stringify` with no normalization, loaders keeping `.trim()`, leaves `prompt-equivalence.baseline.json` untouched: verified by reading `system-prompt.ts:69-72`, `mini-skills.ts:99`, `genui-packs.ts:55` (trim or parse on the raw string only) | the round-trip itself is the emitter test's job.
- Raw descriptors cannot be embedded; derived rows can: measured 1,103,889 bytes across 82 `controls/*/*.md` versus the 19,600-char rendered budget (`dogfood-inventory.ts:152`).
- The `./agent` import closure has no JSON value import and no cross-package value import, so plain Node can load it once fs is gone: verified two layers deep (`grep "from '\.\./" src/agent` non-type; `grep ^import` on `catalog/conformance.ts`, `protocol.ts`, `corpus/text-similarity.ts`, `corpus/heal.ts`, `catalog/naming.ts` returned no value imports; the six `.json` value importers are all under `catalog/{default,a2ui-basic,personas}`) | full closure unverified until the smoke test runs.
- The embed never enters a browser bundle, so `npm run size` is unaffected: verified by `gates.test.ts:72-79` (root barrel re-exports nothing from `src/agent/`) and `grep "a2ui/agent" app/src devtools/src site` (only the pure `agent/meta-line` and `agent/agent-transport` subpaths).
- Node runs `.ts` from `.mjs` scripts without a flag: verified `node --version` = v24.9.0 and the `generate-props.mjs:23` precedent.
- `dogfood: true` throws in the deployed Worker today: verified by code read only (`fs-shim-content.ts` keys, `worker/index.ts:254,297`, `system-prompt.ts:331-333`, `site/pages/gen-ui-live.ts:112`) | not reproduced live.
- `wrangler deploy --dry-run --outdir` works as a bundle gate: `dist/` exists locally and `wrangler ^4.112.0` is a devDependency (`package.json:51`) | the dry-run itself unverified; the `worker-retire` accept pays `npm run build` first.
- The freshness test can live in the jsdom `packages` project only if the generator resolves from `process.cwd()`: verified by `build-dogfood-assets.mjs:28-34` and the `vitest.config.ts:52-54` comment.
- Build runs after #1814 merges: the handoff says so; shared surface is `publish-packages.mjs`, root `AGENTS.md` Never hand-edit, `check:scripts`, `a2ui/AGENTS.md`, the four catalog `factories.ts` (`.sdlc/work/no-barrels/planner-L3-4.md:111-114,175`).

## Rejected alternatives

- `readFileSync(new URL(…, import.meta.url))` plus copying `.md` into `dist/`: breaks under the vite-temp bundle (TKT-0044, `mini-skills.ts:52-58`), still needs the Worker shim, and the dogfood walk reads another package's source tree that a2ui's dist never carries.
- Vite `?raw` or `import.meta.glob` imports: tsc passes `?raw` through verbatim (publish header, ADR-0156 removed one for this), and glob is Vite-only; neither reaches esbuild or plain Node.
- ADR-0137 cl.4's "prompt-source injection seam" (consumer supplies assets): leaves the hand list and the shim in place for the Worker and the docs site; it can be added later on top of `asset-source.ts` without a break, but it is not the embed.
- Generate `fs-shim-content.ts` instead of the loaders' input (the issue's literal "generate the Worker shim"): keeps `node:fs`, the alias, the process shim and the npm exclusion; it only automates the list the design makes unnecessary.
- Embed raw descriptors for dogfood: 1.1 MB in git, in the Worker bundle and in the tarball, for a 19.6 KB rendered output.
- One generated file for everything: the two outputs change on different cadences (prompt edits vs fleet edits) and have different owners; two files keep diffs legible.

## Risks

- Cross-package regeneration churn: every `controls/*/*.md` edit that changes a first sentence, a `tag:` or an attribute reds a2ui's freshness gate until `generate-agent-assets.mjs` runs; if that friction is unacceptable, arm two of the fork (components-owned snapshot) is the fallback.
- A transitive `.json` or `@agent-ui/*` value import deeper than two layers would make the published `./agent` fail in plain Node; the smoke test is the only full proof, and it runs late in the plan.
- `dogfood-tag-set-equality.test.ts` now compares two committed artifacts (`DOGFOOD_FLEET` and components' `DOGFOOD_TAGS`); both freshness gates must stay in `npm test` or the comparison stops meaning "the real fleet".
- `wrangler deploy --dry-run` may need account context or a built `dist/`; if it cannot run in CI the Worker bundle keeps the GH #811 blind spot and the retirement leaf must be verified by a real deploy.
- The new ADR's number depends on #1814 landing; pinning it early collides with ADR-0233.
