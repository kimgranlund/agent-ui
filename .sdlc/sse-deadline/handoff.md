## Goal
Bound the Anthropic provider's network wait: a stall guard on the response so a connection that goes silent mid-stream fails the turn visibly instead of hanging, plus a deadline for the first response. Tracks GH #1797, gap (c) of (a) to (d). Gaps (a) dev-proxy abort (PR #1804) and (b) tool-dispatch timeout are separate branches; do not depend on them and do not touch `dev-proxy-plugin.ts` or `tool-dispatch.ts`.

## Context
Verified (code reading, 2026-10-05) in `packages/agent-ui/a2ui/src/agent/providers/anthropic.ts` `runRound` (about lines 304-380): `fetch(endpoint, {..., signal})` has no timeout, and the SSE loop `for (;;) { const { done, value } = await reader.read() ... }` has no stall guard, so a connection that stops sending bytes hangs the turn until the user disconnects. Existing behaviour to preserve: non-OK responses throw `anthropicProvider: upstream error ...` (TKT-0075); SSE error frames throw; the `finally` releases the reader (`reader.cancel()`); text fragments are yielded AS THEY ARRIVE (ADR-0146 live progress, load-bearing); the GH #49 tool loop (`MAX_TOOL_ROUNDS = 4`, `MAX_CALLS_PER_ROUND = 4`) is unchanged; the caller's `signal` keeps its meaning. Existing tests: `src/live-agent/anthropic-sse.test.ts`, `anthropic-tool-loop.test.ts`, `anthropic-request-body.test.ts`, `provider-dispatch.test.ts` (read them; they pin behaviour).

Required behaviour (decide details from the code):
- Exported constants, generous so they never fire on healthy long turns (reasoning at high effort is slow): `ANTHROPIC_FIRST_BYTE_TIMEOUT_MS` (default 60_000: time from request start to the response headers) and `ANTHROPIC_STALL_TIMEOUT_MS` (default 60_000: maximum silence between two reads of the body). No overall wall-clock cap in this change.
- First-byte timeout: combine the caller's `signal` with `AbortSignal.timeout(first-byte)` for the `fetch` only. If it fires, throw an `Error` whose message names the provider and the limit (for example `anthropicProvider: no response within 60000 ms`). A caller abort is NOT relabelled as a timeout.
- Stall guard: race each `reader.read()` against a timer reset per read; on silence beyond the limit, cancel the reader (the existing `finally` does it), and throw `anthropicProvider: stream stalled for 60000 ms`. Clear the timer on every settle (no leaked timers). The guard must not delay or buffer fragments (still yield as they arrive).
- Zero change to the request body, headers and the yielded text for a healthy stream (byte-identical behaviour; the existing tests prove it).
- Test seam: prefer `vi.useFakeTimers()` with a stub `fetch` (see how `anthropic-tool-loop.test.ts` stubs fetch). If a test needs a smaller limit, an optional parameter on `anthropicProvider(opts)` is allowed ONLY if existing callers and tests are unaffected.

Tests (extend an existing anthropic test file or add `src/live-agent/anthropic-timeouts.test.ts`): (1) a fetch that never resolves rejects at the first-byte limit with the named message; (2) a body that sends a frame then goes silent rejects at the stall limit with the named message, and the reader is cancelled; (3) a healthy stream with gaps shorter than the limit completes and yields every fragment (negative control); (4) a caller abort before the limit is not relabelled; (5) no timer remains pending after a normal completion. Prove red-then-green: run the new tests against the base `anthropic.ts` in a throwaway worktree created with a LITERAL resolvable path, `git worktree add --detach "$SDLC_TMP_WORKTREES/base" HEAD` (the stray-worktree hook denies a variable path), and prove one mutant (for example the stall race removed) fails the matching test.
