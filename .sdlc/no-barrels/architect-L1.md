## Approach

The barrel problem is two coupled hand-maintained lists that both run side effects: `controls/index.ts` (87 `export *` lines, each executing a top-level `customElements.define`) and `component-styles.css` (one `@import` per control, "append-only, do not reorder"). Every runtime importer of the family barrel pays the whole fleet: the four A2UI catalog factory modules (`default`, `a2ui-basic`, `concierge`, `croupier`) do this, so any `@agent-ui/app` or renderer consumer carries all 87 controls eagerly. Measured with a Rolldown stub of the barrel: `app .` eager 114640 → 67415 B gz, `app/surface-host` 94682 → 28112 B gz; Rolldown also warns `INEFFECTIVE_DYNAMIC_IMPORT` because the barrel defeats text-field's lazy calendar/color-picker today. `npm run size` is red on main already (app marginal 106987 vs 106559 B gz, exit 1).

The design replaces the lists with three generated artifacts derived from the descriptors (the ADR-0173 vehicle: generated, committed, regenerated by `scripts/generate-controls.mjs`, drift-gated by regenerate-and-compare). Per-control entry modules stay exactly as they are: each `{name}.ts` already self-defines and already imports its real sibling dependencies (`table.ts` imports button/checkbox/pagination/radio; `card.ts` its regions). What is new is declaring that truth: the descriptor gains `uses: [ui-button, …]`, gated two ways: `uses` ≡ sibling control folders reached by the module's static + `import()` specifiers with `import type` stripped (reusing `measure-size.mjs`'s `relativeSpecifiers` shape, since `tree-shake.test.ts`'s crawler cannot see `import()`), and `{name}.css`'s `@import` prologue ≡ the sheets of `uses`. A control sheet is therefore self-contained the way its module is: importing `controls/table.css` brings button/checkbox/pagination/radio CSS along. From `uses` the generator emits `controls/registry.gen.ts` (tag → `{ load: () => import(...), css: './x/x.css', uses }`), `all.gen.ts` + `all.gen.css` (the one demo-only entry, exports nothing, bare imports only), and the `./controls/{name}` + `./controls/{name}.css` block of `package.json` exports (explicit entries, generator-written, because esm.sh behaviour for exports *patterns* is unverified while explicit entries are proven CDN-safe by `release-facts.md`).

The CSS order guarantee is replaced, not dropped. The only proven order dependence is `card.css:14` (seeds `--ui-container-bg` by later-source over `_surface/container.css` at equal `:where()` specificity); the cross-family seams (`_surface/container.css`, `container-box.css`, `_chart/chart-axis.css`) cannot be `@import`ed from control sheets because a browser applies every duplicate `@import` separately and a second seam copy would land after card.css and reset its seed. So the seams move to one once-linked `shared-styles.css` between the foundation and any control sheet (the host contract becomes four lines), control sheets never import a `_` seam (gate), and control-to-control order is proven free by a browser shuffle gate (random link order vs canonical, computed styles equal) plus a "foreign `:where(ui-other)`" ban so duplicated control sheets are order-safe. Control `.ts` stays style-free (ADR-0003's invariant kept); the new host-side `ensureControls(tags, { css })` loader links sheets for the tags it itself defined, with a sync fast path when every tag is already defined and `css: 'host'` for hosts that link `all.css` themselves.

The dynamic host is the renderer. `CatalogEntry` gains `controls?: ControlLoader` (a 4th `register()` arg); default and a2ui-basic wire the components registry, factory modules stop importing the fleet, and `PersonaCatalogPackage.controls` lets a fragment declare `{ tag, load, css? }` records (components-package-agnostic, merged by `composePersonaCatalogs`; `PersonaCatalogManifest` stays Node-safe). The renderer does not open a new upgrade path: `tree.apply` is sync today and parents (tabs, radio-group) see upgraded children in `connected()`; creating elements before `define` would invert that. So when a loader is present and some tags are undefined, the surface's messages queue and drain after `ensure` resolves (order preserved); load failure emits `CONTROL_LOAD` and the existing `a2ui-placeholder` path renders. Absent loader = byte-identical sync behaviour, so every existing host and test keeps working. Honest `sideEffects` (`./src/controls/**`, `./src/all.gen.ts`, `./src/**/*.css`) goes on components and the other eight packages; `publish-packages.mjs` gains the same `./src/`→`./dist/` rewrite for it. Scope ruling: app/code/data/router already ship per-arm subpaths with lazy heavy arms (ADR-0139/0197), so they get `sideEffects` only; the restructure is components + a2ui.

## Constraints and assumptions

- Every control module self-defines and imports its sibling deps; the barrel adds nothing but eagerness: verified by `grep "^import" controls/*/*.ts` (43 sibling edges) and `controls/index.ts` header.
- `dom/`, `reactive/`, `traits/` have no top-level side effects; `icons` root pure, `./phosphor` not: verified by line-anchored grep only | builder re-verifies by bundling `import { signal } from '@agent-ui/components'` with `sideEffects` and asserting zero `dom/` bytes.
- Pre-upgrade property sets are safe: verified `dom/element.ts:55-58,204-224` (`upgradeProperty` captures own props).
- `tree.apply` is synchronous and factories set JS properties: verified `renderer.ts:372`, `default/factories.ts:207`.
- Parents may read children in `connected()` (tabs, radio-group): verified by reading `tabs.ts:120-316`, `radio-group.ts:117-183`; hence defer-then-build, never create-before-define.
- `card.css` depends on landing after `container.css`: verified `card.css:14`; no other control sheet declares a foreign `:where(ui-other)` rule: verified by selector grep (only `:scope ui-x` descendant rules, specificity-decided).
- Node resolves multi-`*` exports patterns and `*.css` over `*`: verified with a scratch package on Node 24.9; Vite 8 resolves them too: verified via `pluginContainer.resolveId`. esm.sh with patterns: unverified (lit ships none), hence explicit entries.
- Vite copies `new URL('./x.css', import.meta.url)` as an untransformed asset (no lightningcss `light-dark()` polyfill, `vite.config.ts:69-78`; nested `@import`s unresolved): unverified by run, known Vite asset semantics; hence the `css` resolver seam and `'host'` mode.
- Vite dev serves a `<link>` to a package CSS path as CSS: unverified.
- jsdom never fires `load` on `<link>`: known, drives "link only what the loader defined".
- Descriptor parser accepts unknown top-level keys (generic scalars/sequences): verified `component-descriptor.ts:279-289`; validation list has no unknown-key code.
- `styling-gates.test.ts` scans only `@scope` bodies; `button-css.test.ts` slices by `indexOf(':where(ui-button)')`: verified; an `@import` prologue is invisible to both.
- Publish rewrites only `exports` `./src/`→`./dist/`: verified `publish-packages.mjs:111-145`; tests excluded from emit: verified `tsconfig.build.json:44`.
- `measure-size.mjs` T5 reads `./controls/*` keys from `package.json` and would pass vacuously on patterns: verified `:323-330`; app leg already separates eager vs lazy chunks: verified `/tmp/size-baseline.txt:432-433`.
- Baseline `npm run size` exit 1 on main (app marginal over): verified `/tmp/size-baseline.txt:451`.

## Rejected alternatives

- Controls importing their own CSS from `.ts` (constructable sheets or `import './x.css'`): ADR-0003 behaviour-only invariant, tsc-verbatim publish cannot bundle CSS, CDN path breaks.
- Seams `@import`ed from each control sheet: duplicate `@import`s re-apply in browsers and reset `card.css`'s later-source seed.
- `@layer` to encode order: changes precedence against every unlayered host/site rule; touches 87 sheets and every CSS probe for a guarantee the seam sheet gives for free.
- Exports subpath patterns instead of explicit entries: esm.sh unverified; T5 enumeration would go vacuous; kept as a later simplification.
- Deriving `uses` from the import graph alone (no descriptor field): the descriptor is the documented contract (ADR-0173); a declared field plus a bijection gate catches both phantom and missing deps and feeds the site.
- Create elements before definitions and rely on upgrade: opens a parent-sees-undefined-children path no test covers.
- One registry spanning descriptors, catalogs and sidecars: layering forbids components knowing a2ui; the join is at runtime (`WidgetFactory.tag` → `registry.gen.ts`), ADR-0232 sidecars stay prompt-only.
- Keeping `./components` as a deprecated alias: Kim's ruling (never used in package code); an alias is a barrel by another name.

## Risks

- `all.gen.css` regenerates in sorted order while today's barrel is addition order; the first regeneration is itself the shuffle experiment: run the visual shard before and after; a baseline diff is a finding, not a refresh. Same for `dogfood-assets-freshness` and `theme-provider-build-fixture`.
- The app size row stays red on every intermediate slice until `a2ui-catalogs` lands (ADR-0197 cl.5 closes upward re-bases): land it early or get a ruling.
- The loader's default `new URL` CSS path on esm.sh is unverified (esm.sh rewrites module URLs); the CDN recipe must link `all.css` or per-control sheets explicitly.
- A `uses` closure under-declared in one descriptor ships a half-styled control; both gates must bite (negative controls) before the codemod lands.
- `sideEffects` on a package whose `dom/` hides a top-level effect would let a bundler drop it; the builder's bundle check is the proof.
- Deferred apply changes surface timing for hosts that wire `controls`; any host test asserting DOM synchronously after `apply` on a fresh page needs the sync fast path to hold (all tags pre-defined).
