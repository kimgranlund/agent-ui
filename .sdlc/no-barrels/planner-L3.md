## Risks
- CSS order: the prologue duplicates (step 3) and the first sorted regeneration (step 4) can surface an order dependence beyond `card.css:14`. The shuffle gate lands before any reordering; a visual or `__baselines__` difference is a finding to stop on, never a refresh.
- Step 5's deferral is the riskiest logic (queue order, `finalize` and `deleteSurface` while pending, `dispose`, late resolutions). It is L4 and fully covered by fake-loader tests before step 6 turns it on for the built-in catalogs.
- Step 6 may break more a2ui, app, devtools and site tests than expected (any test that leaned on the factories' fleet import or asserts the DOM synchronously); the fix rule is fixed (import `all` in the test), but the volume is unknown.
- The app reach gate's tag scan is regex-based and may flag a tag inside a string or comment; the builder narrows the pattern, never allowlists a real gap.
- The `all.gen.ts` family row could measure above 72192 B gz; step 8 stops and reports instead of re-basing upward.
- The default URL CSS mode is unverified on esm.sh (it rewrites module URLs); the CDN recipe links sheets explicitly, and built-in catalogs use `'host'`.
- The three base browser reds may be load-flaky on this host (load average 10 to 16), which makes "no new failure" comparisons noisy; re-run a lone extra failure in isolation.
- Another host without the Playwright 1.61.1 browsers cannot run any browser criterion until `npx playwright install chromium webkit` runs there.
