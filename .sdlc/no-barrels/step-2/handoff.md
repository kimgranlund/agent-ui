## Task goal
Design how agent-ui stops relying on barrels (the `src/controls/index.ts` family barrel and the `component-styles.css` CSS barrel, plus the other package barrels where the same problem applies) so that consumers load only the controls they use, tree-shaking works, and adding a control no longer means hand-editing shared lists. Design only: no code, no edits.

## Step 2: Declare `uses` in every descriptor, gated against the import graph
level: L3
### Read first
- `packages/agent-ui/components/AGENTS.md`
### Do
Depends on: step 1 (the ADR the records cite). Settled interfaces:
- New pure module `packages/agent-ui/components/src/descriptor/control-graph.ts` (no `node:*` import; callers pass a reader, so the CLI, the gates and later the generator share one implementation, the ADR-0173 precedent at `scripts/generate-props.mjs:21`):
  - `interface FleetEntry { readonly tag: string; readonly folder: string; readonly name: string }`: one per `controls/{folder}/{name}.md` with `{folder}` not `_`-prefixed (the family-coherence discovery shape); entry module `{folder}/{name}.ts`, sheet `{folder}/{name}.css`.
  - `relativeSpecifiers(source: string): string[]`: relative specifiers of `from '…'`, bare `import '…'` and dynamic `import('…')`, with `import type` and `export type` statements stripped across lines (the `scripts/measure-size.mjs:387` shape, widened to multi-line type imports).
  - `deriveUses(entry: FleetEntry, fleet: readonly FleetEntry[], read: (controlsRelPath: string) => string | undefined): string[]`: walk relative specifiers from the entry module, through non-entry modules under `src/controls/`, stopping at (and recording) other fleet entry modules; return their tags sorted. At HEAD this yields 39 edges across 21 controls, including the text-field and color-picker cycle and the same-folder `ui-radio-group` uses `ui-radio` (planner crawl, see Assumptions).
- `component-descriptor.ts`: add `'BAD_USES'` to `DESCRIPTOR_CODES`. `uses` stays OUT of `FIELD_SHAPE`, because every `FIELD_SHAPE` key is required (`validateComponentDescriptor`, `component-descriptor.ts:367-375`) and app descriptors run through the same validator (`app/src/controls/*/*.test.ts`). When present, `uses` must parse as a sequence of bare scalars matching `^ui-[a-z][a-z0-9-]*$`, without duplicates and without the descriptor's own tag; anything else is `BAD_USES`. An inline flow list parses as a scalar (`parseDescriptor`, `:280-289`), so it is `BAD_USES` by construction; the grammar is a block sequence, and `uses: []` when empty.
- New `scripts/codemod-uses.mjs` (imports `control-graph.ts` directly, as `generate-props.mjs` imports `generate-props.ts`): writes each fleet descriptor's `uses` block on the line directly after its `extends:` line (a required field every fleet descriptor has), sorted; `--check` writes nothing and exits 1 naming each out-of-sync file. Run it once over the fleet. Only `*.md` files change in this step; `generate-props.ts` reads only `tag` and `attributes` (`:86-94`), so no `*.props.gen.ts` moves.
- Gates: `src/descriptor/control-graph.test.ts` (specifier and crawl unit tests on fixtures: static, bare, dynamic, multi-line `import type` excluded, walk through a helper module, a cycle) and `src/controls/uses-driftwire.test.ts` (every fleet descriptor declares `uses`; declared equals `deriveUses`; the `BAD_USES` cases; negative controls: a planted phantom edge and a planted missing edge each fail). The gates bite on fixtures before anything relies on the codemod output.
- Records: `.claude/docs/references/component-packaging.md` (descriptor gains `uses`, how to sync it), `.claude/skills/component-standards/references/descriptor-generation.md` (field list), `.claude/skills/component-build/SKILL.md` (integrate step: run `node scripts/codemod-uses.mjs`), `packages/agent-ui/components/AGENTS.md` (Controls section).
- Typecheck, for this and every later step that changes `.ts`: `npm run check` (root `tsc`, then `check:site`, `check:tools`, `check:scripts`; root `tsconfig.json` includes `packages/agent-ui/*/src`, tests included) is a guard on steps 2 to 8, not only on step 8. This departs from the whole-gates-on-the-final-step default on purpose (plan review finding): `steps.py split --only N` refuses a red guard, so a type error left by step N could never be fixed at step 8, while a guard on step N is checked by step N's own verifier, so a red never reaches step N+1.
- Scope, for this and every later step: the scope guard is cumulative. A plain /chain commits nothing (`chain/SKILL.md:42`), so the diff against `$SDLC_BASE_SHA` carries every earlier step's files, and each step's allow-list repeats the earlier steps' paths (the ADR paths in step 8's list are deliberate). Each list is one `grep -vxE` pattern, the E form `steps.py widen` recognizes. Here it admits only descriptors (`controls/{folder}/{name}.md`, never a `_` folder) and the named test under `controls/`, which subsumes the old "no controls `.ts` or `.css`" guard; that guard is gone because its `grep -v` would count as a second scope span and make `steps.py widen` refuse.
