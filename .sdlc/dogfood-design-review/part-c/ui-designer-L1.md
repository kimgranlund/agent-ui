- packages/agent-ui/components/src/controls/gauge/gauge.css:111: shots/charts__gauge-demo__1000__light.png and __400__dark.png. Every ring's progress arc is broken into 3 to 5 disjoint dashes scattered round the circle, so CPU 72% looks like a dashed track rather than one sweep from 12 o'clock. Cause: `vector-effect: non-scaling-stroke` on `[data-part='progress']` makes the browser read `stroke-dasharray`/`stroke-dashoffset` in screen px, but gauge-math.ts:117 passes the circumference in viewBox units, so the svg scales up about 5x and the dash pattern repeats. Fix: drop `vector-effect` from the progress circle and set the stroke width in user units, or set `pathLength="100"` on the circle with dasharray 100 and dashoffset `100 - value`. Measurable: the lint fails any element that has a computed `vector-effect: non-scaling-stroke` together with a `stroke-dasharray` other than `none`.
- packages/agent-ui/components/src/controls/stat/stat.css:58: shots/data__stat-demo__1000__light.png, Ring variant. "47 / 50" spills past both sides of the donut and its glyphs cross the ring stroke, and "pending" overflows the same way. Cause: the ring is a fixed 4.5em with a 0.5em stroke (stat.css:58-59), while the figure sharing the `figure` area (stat.css:141-143) keeps the heading type size (stat.css:91), so any figure wider than 3.5em of host type overflows the hole. Fix: in `[variant='ring']`, size the ring from the figure, e.g. `--ui-stat-ring-size: max(4.5em, <value inline-size> + 2 * thickness + inset)` (put the value in an inline-size container or measure it), or drop the ring figure to the body-large row and keep it inside the hole. Measurable: the value part's bounding box must fit inside the ring's inner circle (box diagonal <= ring-size - 2 * thickness).
- packages/agent-ui/components/src/controls/breadcrumb/breadcrumb.css:53: shots/navigation__breadcrumb-demo__1000__light.png and __400__dark.png. The crumbs render as raw browser links (UA blue #0000EE with underlines, and lavender in dark) at 12px label-medium, smaller than the prose next to them, so the trail reads as an unstyled HTML fragment and not a fleet control. Cause: the styles block gives author `<a>` crumbs only a focus ring (breadcrumb.css:83-86) and never sets their ink or text-decoration. Fix: add `:scope > a { color: var(--ui-breadcrumb-link-ink /* neutral-on-surface-variant */); text-decoration: none }` plus a hover rule (underline, on-surface ink), and step the crumb type up to the body-medium row. Measurable: no anchor inside a `ui-*` host may compute to the UA link colours rgb(0,0,238) or rgb(85,26,139).
- packages/agent-ui/components/src/controls/table/table.ts:429: shots/data__table-demo__1000__light.png, full-capability report. Sortable headers ("Account", "Seats", "MRR (USD)", "Signed up") are primary-blue ghost buttons that read as links. Their label sits about 10px inside the column's cell text (Account header x 348 against cell text x 338), and end-aligned number headers stop about 9px short of the numbers. The plain headers on the same page ("Region", "Revenue (USD)" in Default-off baseline) are neutral and flush, so the two tables disagree. Cause: the composed `ui-button variant="ghost"` brings its own inline padding and primary ink into the `<th>`, which already has the cell padding (table.css:104-115). Fix: inside `th`, give the sort button a negative inline margin equal to its own padding-inline, or zero its padding and keep the hover wash on a pseudo-element, and repoint its ink to the header's neutral ink, keeping the sort glyph as the only affordance. Measurable: each `th` label's text-start x (text-end x for `data-type=number`) equals the same column's `td` text x within 1px.
- packages/agent-ui/components/src/controls/table/table.css:66: shots/data__table-demo__1000__light.png. Cause: `--ui-table-row-selected-ink: primary-high` is applied to every `td` (table.css:135-137). - packages/agent-ui/components/src/controls/table/table.css:149: shots/data__table-demo__400__dark.png and __400__light.png. At 400px both tables lose their pager: a blank band remains under the last row where "Previous 1 2 3 Next" sits at 1000px, so the table looks cut off. The cause is not visible in CSS, but there is a control case: navigation__pagination-demo__400__dark.png shows the same composed footer pager rendering fine on a 2-column table at 400px, so the failure is specific to a table wider than its host. The footer is `display:flex; justify-content:flex-end` outside the scroll container, so it most likely grows to the 6-column table's min content and the end-aligned pager lands off-canvas. Fix: probe the footer and pager rects at 400px, then constrain the footer to the host's inline size (`min-inline-size: 0; max-inline-size: 100%`) or let it wrap and start-align when narrow. Measurable: every visible child of `[data-part='footer']` must intersect the host's own rect (metrics.json `offRight` did not catch this, so the lint needs a host-relative test and not a viewport test).

- packages/agent-ui/components/src/controls/sparkline/sparkline.css:31: shots/data__sparkline-demo__400__dark.png, Sizing. Cause: the box is exactly `1lh` with `vertical-align: text-bottom` (sparkline.css:43), and the polyline spans the full 0..100 viewBox with `overflow: visible`, so peaks touch the neighbouring line boxes. - packages/agent-ui/components/src/controls/button/button.css:88: shots/navigation__pagination-demo__1000__light.png (table footer) and data__table-demo__1000__light.png. On page 1 the disabled "Previous" gets a grey filled pill next to the tonal current page "1", so it reads as a pressed or selected stop. The enabled "Previous" in the standalone pager is bare text. Cause: `ui-button[disabled]` repaints `--ui-button-bg` to `neutral-surface-high` for every variant, ghost included (button.css:88-93), and pagination stamps ghost stops (pagination.ts:143-145). Fix: `:where(ui-button[variant='ghost'][disabled]) { --ui-button-bg: transparent }` (and the same for its hover and active values), so a disabled ghost only mutes its ink. This is part-a's family; it is reported here because it shows on these pages. Measurable: a disabled ghost button's computed background is transparent.
- packages/agent-ui/components/src/controls/timeline-item/timeline-item.css:244: shots/data__timeline-demo__1000__light.png and __400__dark.png. Done steps are hairline check glyphs (about 1px stroke, pale green) while the current step is an 8px solid dot, so the markers do not read as one set. The checks also sit about 2px above the label's optical centre, and the rail starts below the check and not from its centre. Cause: a status glyph replaces the dot (timeline-item.css:244-246) at the content-icon size, centred on the marker-box (timeline-item.css:253) and not on the label's line box. Measurable: marker centre y equals the label's first-line centre y within 1px, and all status markers share one outer diameter.
- packages/agent-ui/components/src/controls/tabs/tabs.css:321: shots/navigation__tabs-demo__1000__light.png and __400__dark.png, Overflow menu. - packages/agent-ui/components/src/controls/card/card.css:98: shots/containers__card-demo__1000__light.png, Nested radius. The nested card's corner is visibly the same as the outer card's (about 14px against 15px), while the demo copy says it "shrinks with the parent padding". Cause: `--md-sys-card-radius` is the first term of `--ui-card-radius`, so whenever the derived token is defined it short-circuits the `--ui-card-child-radius` chain and every card gets 3n regardless of depth. Fix (decide): if a nested card sits one level down, read `--ui-card-child-radius` before `--md-sys-card-radius` for a card inside a card (or publish `--md-sys-widget-radius` as the child radius). If Kim's "cards keep their level radius" ruling covers nesting, rewrite the demo copy and descriptor line instead. Measurable: a ui-card inside ui-card-content has a radius below its parent's.
