## Goal
Give the shared tool dispatch a per-call deadline so a tool executor that never settles cannot hang a turn. Tracks GH #1797, gap (b) of (a) to (d); (a) dev-proxy abort is a separate PR (do not depend on it, do not touch `dev-proxy-plugin.ts`).

## Context
Verified (code reading, 2026-10-05): `packages/agent-ui/a2ui/tools/agent/integrations/tool-dispatch.ts` `buildToolDispatch` returns `executeTool(name, input, callSignal)` that validates input then does `return match.execute(input, ctx)` with `ctx.signal = callSignal ?? signal`. It has NO timeout. Only the built-in fetch tools (`integrations/fetch-json.ts`, `FETCH_TIMEOUT_MS = 10_000` via `AbortSignal.any([AbortSignal.timeout(...), signal])`) and the MCP client (`integrations/mcp/client.ts`, `DEFAULT_TIMEOUT_MS = 10_000` per HTTP request) bound themselves. A custom executor that ignores `ctx.signal` is unbounded. The thrown-executor path already exists: a throw becomes an `is_error` tool_result the model can read (`anthropic.ts` around lines 428-430, GH #49), so a timeout must travel that path by throwing an `Error` with a clear message, never by hanging or by killing the turn.

Required behaviour (decide details from the code; if a real design question appears, stop and report it as a design question instead of guessing):
- A constant `TOOL_CALL_TIMEOUT_MS`, exported, strictly GREATER than the inner 10 s timeouts (default 30_000), so it never pre-empts them: the inner timeout stays the normal path, this is the backstop. Do not change the inner timeouts and do not double-wrap them (document the relationship in a comment: backstop above, not a replacement).
- Combine the deadline with the existing signal: `ctx.signal` becomes `AbortSignal.any([AbortSignal.timeout(TOOL_CALL_TIMEOUT_MS), callSignal ?? signal])` (guard the case where both signals are absent), so cooperative executors are cancelled.
- Also race the executor promise against the deadline so a NON-cooperative executor (ignores the signal) still rejects at the deadline with an `Error` whose message names the tool and the limit, e.g. `<name>: tool call timed out after 30000 ms`. Clear the timer when the executor settles (no leaked timers; use a cleared `setTimeout` for the race or confirm `AbortSignal.timeout`'s unref behavior in the Node version used).
- When the outer (turn) signal aborts first, the existing behaviour is kept: the call rejects with the executor's own abort error; do not relabel it as a timeout.
- Zero active manifests still returns `{}` (byte-identical contract, header comment).
- A test seam is allowed (an optional `timeoutMs` parameter or an exported option) ONLY if it does not change the 3-argument signature's meaning for existing callers; prefer fake timers (`vi.useFakeTimers`) with the real constant.

Tests (new file `packages/agent-ui/a2ui/src/live-agent/tool-dispatch-timeout.test.ts`, the precedent location for tools/agent tests is `src/live-agent/`, see `chat-route.test.ts` importing from `../../tools/agent/...`): (1) a never-settling non-cooperative executor rejects at the deadline with the named message; (2) a cooperative executor that honors `ctx.signal` sees it aborted at the deadline; (3) a fast executor resolves and leaves no pending timer (negative control); (4) an outer-signal abort before the deadline is NOT relabelled as a timeout; (5) zero active manifests still returns `{}`.
