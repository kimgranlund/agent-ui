## Goal
Give every agent-emittable catalog type machine-readable selection guidance (`intents` and `notFor`, with confusable pairs) that the catalog-derived prompt inventory shows to the model and that evals and validators can read, then update every skill, command, agent and doc that describes the catalog, descriptors, or prompt inventory so none goes stale.

## Context
Origin: a comparison of agent-ui with the maison gen-ui-system reference (`/Users/kimgranlund/Projects/maison/ui-kit-maison/docs/reference/gen-ui-system`, read-only; its README marks its schema and example as historical and many rules as "normative target"). Findings relevant here:
- Maison's component manifest carries `ontology{category, role, intents[]}`, `composition.allowedChildren`/`allowedContexts`, and `constraints.notFor[]` (see `schemas/component-manifest.schema.json`, `examples/button.manifest.json`, `specs/gen-ui-ontology.md` section Minimal shape and Test for inclusion, `specs/gen-ui-manifests.md`). Its ontology rule: include only the system-specific delta a model would not infer, and only if it disambiguates similar components, aids deterministic retrieval, or encodes a domain choice.
- agent-ui has no machine-readable equivalent: a search of component descriptors for `notFor`, `whenToUse`, `intents`, `related` found 0 hits. The guidance exists as prose (the `component-catalog` skill, the choosing guide, mini-skills such as `variant-picker`: "<=3 members -> SegmentedControl").
- agent-ui side to read: component descriptors `packages/agent-ui/components/src/controls/*/*.md` (attributes fence, frontmatter), `packages/agent-ui/a2ui/src/**/catalog/default/catalog.json`, `packages/agent-ui/a2ui/src/agent/system-prompt.ts` (the catalog-derived inventory), `mini-skills.ts`, `prompt-drift.test.ts`, `prompt-equivalence.baseline.json` and its deliberate-change recapture flow (skill `a2ui-prompt-authoring`), ADR-0091 (mini-skills), ADR-0135 (agent config and prompt files), ADR-0173 (descriptor generation of `.props.gen.ts`), ADR-0169 (multi-catalog), `.claude/docs/references/agent-model.md`.

Open design decisions the architect must resolve with evidence, not assume: (a) where the data lives (descriptor frontmatter vs catalog.json vs a new generated artifact) and what the single source of truth is, given descriptors already generate `.props.gen.ts` and are drift-gated; (b) the field shape (`intents`, `notFor` as component ids with a one-line reason, optional `confusableWith`), and the inclusion test so it is a delta not a restatement; (c) how the inventory renders it and the byte cost against the prompt budget (the inventory is byte-pinned by `prompt-equivalence`); (d) coverage rule: which types must carry it (agent-emittable only; the catalog-invisible packages router/code/data are out) and a gate that fails a new emittable type without it; (e) multi-catalog and derived-catalog (ADR-0169, `composeCatalog`) behavior; (f) whether this earns an ADR (a contract-changing fork is proposed, never self-ratified).

## Constraints

- Prompt surface is byte-pinned: any change that moves the baseline uses the deliberate-change recapture flow from `a2ui-prompt-authoring`, never a silent edit.
- Docs, skills, commands, agents and ADR notes that describe catalog, descriptor schema, prompt inventory or selection guidance must be updated in the same change: at minimum check `.claude/skills/component-catalog`, `component-packaging`, `component-standards`, `component-design`, `a2ui-payload-authoring`, `a2ui-prompt-authoring`, `a2ui-multi-catalog`, `.claude/agents/*`, `.claude/docs/references/` (agent-model, choosing guide, descriptor schema docs), `.claude/docs/references` descriptor schema source, CLAUDE.md/AGENTS.md, and `doc-standards` if a new doc type or status dialect appears.
