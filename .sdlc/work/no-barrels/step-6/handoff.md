## Task goal
Design how agent-ui stops relying on barrels (the `src/controls/index.ts` family barrel and the `component-styles.css` CSS barrel, plus the other package barrels where the same problem applies) so that consumers load only the controls they use, tree-shaking works, and adding a control no longer means hand-editing shared lists. Design only: no code, no edits.

- Remove `import '@agent-ui/components/components'` from `a2ui/src/catalog/default/factories.ts:105`, `a2ui-basic/factories.ts:12`, `personas/concierge/factories.ts:53` and `personas/croupier/factories.ts:21`.
- New `a2ui/src/catalog/controls.ts`: `export const builtinControls = createControlLoader(CONTROLS, { css: 'host' })` (from `@agent-ui/components/registry` and `/loader`). `css: 'host'` keeps today's host contract (the host links CSS, ADR-0003's host-page invariant) and never hangs a jsdom test on a `<link>` that never loads. The renderer constructor passes it as the fourth `register` argument for the default and both a2ui-basic registrations (`renderer.ts:198-205`); persona composition inherits it through `composeControlLoaders`. Croupier's package declares `controls: [CONTROLS['ui-playing-card']]`, the in-repo demonstration of the persona seam.
- App hidden dependencies: `app/src/controls/conversation/conversation-composer.ts` renders `ui-button`, `ui-icon`, `ui-menu`, `ui-switch`, and `conversation.ts` renders `ui-icon` and `ui-status-stream`, with no per-control import; today only the factories' fleet import defines them (planner tag-versus-import table). Add the per-control side-effect imports (`@agent-ui/components/controls/{name}`) to each app module that renders a fleet tag it does not import, and move app's four type-only barrel imports (`agent-admin.ts:142`, `conversation-composer.ts:58`, `conversation.ts:73,86`) to the per-control subpaths that export those types.
- New gate `app/src/control-reach.test.ts`: for each `.ts` target in `app/package.json` `exports`, crawl relative and `@agent-ui/components/controls/*` specifiers (static and dynamic) into the components fleet; every fleet tag that a reached app module renders (`<ui-x` in a template, or `createElement('ui-x')`, comments stripped) is defined by a reached fleet entry module; a negative-control fixture that renders `<ui-switch>` without importing it is flagged. Scope is app only: code and router are siblings off components and never relied on a2ui, and devtools renders no `ui-*` tag (planner grep).
- Tests that relied on the factories' fleet import (a2ui, app, devtools, site jsdom; app and rest browser shards) add `import '@agent-ui/components/all'` (tests may import `all`; package code never does), or the per-control imports they need. A test that asserts the DOM synchronously after `ingest` needs its tags defined first, which `all` gives.
- New `a2ui/src/renderer/builtin-controls.test.ts`: a fresh renderer's default, a2ui-basic and derived persona entries carry `controls`; on a jsdom page that defined nothing, a default-catalog surface defers, then renders once the loader has defined its tags; croupier's derived entry routes `ui-playing-card` through its persona record.
- New `a2ui/src/renderer/control-loading.browser.test.ts` (moved here from step 5 by the plan review, because only now does importing the renderer define no fleet tag): the test imports the renderer, `defaultCatalog`, `defaultFactories`, `CONTROLS` (`@agent-ui/components/registry`) and `createControlLoader` (`@agent-ui/components/loader`), and first asserts `customElements.get('ui-table') === undefined`. It then re-registers `defaultCatalog` with `defaultFactories` and `createControlLoader(CONTROLS)` in the default URL mode (one entry per catalog id, the last registration wins: `catalog/types.ts:97`, `catalog/registry.ts:8`), ingests a surface holding one `Table` node (factory `tableFactory`, `default/factories.ts:919`), and after the deferred apply asserts that `ui-table` is defined, that exactly one `link[data-ui-control="ui-table"]` is in `document.head`, and that `getComputedStyle` of the rendered `ui-table` gives `16em` for `--ui-table-min-inline-size` after `.trim()` (declared on `:where(ui-table)`, `table.css:44`).
