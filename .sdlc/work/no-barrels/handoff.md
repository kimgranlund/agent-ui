## Goal
Design how agent-ui stops relying on barrels (the `src/controls/index.ts` family barrel and the `component-styles.css` CSS barrel, plus the other package barrels where the same problem applies) so that consumers load only the controls they use, tree-shaking works, and adding a control no longer means hand-editing shared lists. Design only: no code, no edits.

## Context
Kim's direction (2026-10-05): "we should also not use barrels as it is not very tree-shake friendly and does not scale well." Answers to the two scoping questions: (1) keep ONE demo-only `all` entry point, opt-in, kept out of every package's main exports and never used in package code; per-control entries are the default and the only path used in code. (2) Run an architect first, then a plan, with a PROPOSED ADR that supersedes the barrel part of ADR-0003 (never self-ratified).

Facts verified by reading the repo (re-verify anything you rely on):
- `packages/agent-ui/components/src/controls/index.ts` is the self-defining family barrel: importing it runs every control's top-level `customElements.define` (87 control folders), so it is a side-effect import of the whole family. `packages/agent-ui/components/package.json` has NO `sideEffects` field. The exports map has 92 entries including per-control subpaths like `./controls/button -> ./src/controls/button/button.ts`, plus `./components` (the barrel), `./component-styles.css`, `./foundation-styles.css`, `./base-styles.css`.
- `src/component-styles.css` is a CSS barrel with one `@import` per control, order-sensitive and append-only ("DO NOT REORDER"), placed after `foundation-styles.css`. A control's `.ts` never injects its own CSS. No per-control CSS export exists. `.claude/docs/references/component-packaging.md` says a new control is added by hand to both barrels; ADR-0003 (`.claude/docs/adr/0003-single-file-component-css-barrels-host-page.md`) is the decision being superseded in part.
- Each control folder: authored `{name}.ts`, `{name}.css`, `{name}.md` (descriptor, frontmatter is the generation source for `{name}.props.gen.ts`, ADR-0173, only 11 folders have a generated file today) plus co-located tests. The descriptor has NO requires, uses or dependencies field: `ui-card` cannot declare that it needs `ui-text`.
- The family barrel `@agent-ui/components/components` is imported from `site/pages` (48 files), `site/lib` (4), `packages/agent-ui/app/src/controls/conversation` (3), `agent-admin` (1), `a2ui/src/examples` (2), and the croupier and concierge persona fragments (`a2ui/src/catalog/personas/*`). `component-styles.css` is referenced by several browser tests and host pages.
- The A2UI renderer (`a2ui/src/renderer`) maps catalog types to tags via `mapsTo` and assumes the host already registered the family; it has no on-demand loading.
- Size gate: `scripts/measure-size.mjs`, the family is budgeted as a whole (descriptor comment: 4435 B gz within an 8192 B budget); the app marginal budget has zero headroom and a "final" exception (ADR-0197 cl.5), because the default catalog is eagerly bundled in the app barrel.
- Other barrels exist in other packages (for example `app`, `a2ui` root, `code`, `data`, `icons`); decide which are in scope and say why. The publish script (`scripts/publish/publish-packages.mjs`) compiles with tsc and rewrites exports; the 8 published packages are lockstep.
- Personas (The Croupier, The Quant, The Hotel Concierge, The Maitre d', The Travel Agent, The Curator, The Stylist) may ship bespoke catalog fragments (`catalog/personas/*`, derived `<base>--<persona>` ids via `composeCatalog`); only concierge, croupier and fixture-demo ship one today. The design must work for fragments that add their own controls.

Parts Kim's direction implies (confirm, refine or replace each, with evidence):
1. Per-control entry points only, each module owning its registration; a way for a control to declare what it needs (a `uses` list in descriptor frontmatter) with a gate that checks it against the real imports.
2. A generated registry or loader (per-control record: element module, stylesheet, uses) so the A2UI renderer and other dynamic hosts load only the controls a surface uses, including persona-fragment controls. Reconcile this with the earlier idea of one generated registry (descriptors, catalogs, sidecars).
3. CSS per control: a per-control CSS export or a loader that links CSS beside the JS; retire `component-styles.css` and its order rule (what replaces the order guarantee?).
4. Honest `sideEffects` metadata so bundlers can drop unused modules.
5. A demo-only `all` entry, kept out of main exports.
