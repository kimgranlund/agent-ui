The sitemap carries only demo hrefs for controls that ship a demo page, as it does for service-card: `generateL1` in `scripts/generate-sitemap.mjs` (lines 203-209, GH #1619) writes one L1 entry per tag and uses `{slug}-demo.html` whenever that page exists, and the pattern tier requires that page. The likely fix is `grep -qF board-grid-demo.html site/public/sitemap.json`, which passes now. Every other criterion passed, with one caveat on `npm test`: a single timing assertion in `ui-conversation` failed in the full run and passed 150/150 when run alone (details below).

- The `npm test` failure is in the app package, which this step does not touch. Passing in isolation points to load contention rather than a regression. I made no base-worktree run and did not rerun the full suite.
- `[size]`: the tokens have no `[size]` that cascades from an ancestor, and this step adds no `size` prop. So the cell side is `max(34px, var(--md-sys-height-md))`: the default-size control-height row, which a cascaded `[scale]` re-tables, floored at the 34px target size. I added no `[size]` selector without a prop.
- `CONVERTED` in `props-gen-driftwire.test.ts` is outside criterion 169's allow-list, so board-grid is not in the fleet-wide drift gate. Instead, `board-grid-descriptor.test.ts` carries the same regenerate-and-diff check (the ADR-0173 shape for a converted control). It does not carry the s10 `compareDescriptorToProps` bijection.
- Fill and hug: the host is a block-level grid whose tracks are each one cell side wide, packed to the start. The host fills its container while the cells stay at the control-height side. `[inline]` switches to inline-grid and the host hugs the board. The browser test measures both.
- The preview sets `actionName` in `COMPONENT_SAMPLE_INIT`, not `COMPONENT_INITIAL`. The knob path calls `setAttribute` with the camelCase name, which never reaches `action-name`.
- `SDLC_BASE_SHA` was empty in the builder shell. C166 and C169 ran with it exported from `.sdlc/ui-board-grid/step-1/base-sha` (298fe4ee).
- An ordering trap for the replan: the handoff runs `generate:registry` (item 3.6) before adding the exclusions entry (item 4), so the registry must be regenerated after that entry. That regeneration is done and committed.
