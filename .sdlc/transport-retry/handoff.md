## Goal
Retry the Anthropic provider's upstream request a bounded number of times on transient failures, so a 429 or a 5xx at connection time does not fail the whole turn. Tracks GH #1797, gap (d) of (a) to (d). Never retry tool execution.

Required behaviour (decide details from the code; if a real design question appears, stop and report it as `unresolved:` instead of guessing):
- Retry ONLY before any response body has been consumed or any fragment yielded: the retry wraps the request up to the point where `res` is known good or known to be a retryable failure. Never retry after streaming started (that would duplicate output).
- Retryable: HTTP 429, 500, 502, 503, 504, 529 (Anthropic "overloaded"), and a thrown network error from `fetch` that is not an abort (a `TypeError` from fetch). NOT retryable: any other 4xx (including 401, 403, 400), and a caller abort (the signal is aborted or the error is an `AbortError`): rethrow at once, never relabel, never wait.
- Bound: exported constant `ANTHROPIC_MAX_RETRIES = 2` (so at most 3 attempts) and a backoff schedule, exported (for example `[500, 1500]` ms base, with a small random jitter that tests can pin through an injected `random`/`sleep` seam). Honor a `Retry-After` header (seconds or HTTP-date) when present, capped at 10_000 ms.
- The sleep must be abortable: if the caller's signal aborts during a backoff wait, reject immediately with the abort error and leave no pending timer.
- On exhaustion, throw the SAME error the code throws today for the last failure (same message shape for HTTP errors: `anthropicProvider: upstream error <status>: ...`; the original thrown error for a network failure), so existing tests and the UI's failure path see no new error type.
- Drain or cancel the body of a discarded retryable response (`res.body?.cancel()` / `await res.text().catch(() => {})`) so connections are not leaked.
- Zero change for a healthy first attempt: same request, same single `fetch` call, no added delay.
