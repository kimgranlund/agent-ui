# @agent-ui/a2ui

The A2UI protocol layer. Root `AGENTS.md` and `CLAUDE.md` hold the package DAG, gates and conventions; this file holds only what is local here.

## Byte-pinned prompt stack

- `src/agent/prompts/` (`src/agent/prompts/grammar.md`, the mode files, `src/agent/prompts/mini-skills/`, `src/agent/prompts/genui-packs/`) is byte-pinned by the golden baseline `src/live-agent/prompt-equivalence.baseline.json`, asserted by `src/live-agent/prompt-equivalence.test.ts`.
- The whole composed prompt has a declared character budget (`src/agent/prompt-budget.ts`, ADR-0234), gated by `src/live-agent/prompt-budget.test.ts`. Re-author tersely or re-measure deliberately; never raise the ceiling just to get green.
- After a deliberate prompt change, recapture from the repo root, then diff the baseline: `RECAPTURE_BASELINE=1 npx vitest run --project packages packages/agent-ui/a2ui/src/live-agent/recapture-baseline.test.ts`
- `src/agent/assets.gen.ts` embeds every prompt and `selection.json` sidecar; `src/agent/dogfood-fleet.gen.ts` holds the dogfood rows derived from the components descriptors. After editing a prompt, a sidecar or a components descriptor, run `node scripts/generate-agent-assets.mjs` from the repo root. `src/agent/agent-assets-freshness.test.ts` and `npm run check` stay red until you do.

## Catalogs

| Catalog | Path |
|---|---|
| default | `src/catalog/default/` |
| upstream interop (ADR-0169) | `src/catalog/a2ui-basic/` |
| personas | `src/catalog/personas/` |
| domains (T-0202; empty until W1) | `src/catalog/domains/` |

- Domain catalogs (catalog architecture SPEC `.claude/docs/spec/a2ui-catalog-architecture.spec.md`): a domain is a shared fragment with the persona fragment's shape, listed in `src/catalog/domains/index.ts` and `manifests.ts`, the `DOMAINS` table in `src/catalog/records.ts` and `DOMAIN_FRAGMENTS` in `tools/registry/load.ts` (held equal by `src/catalog/domains.test.ts` and `src/registry/registry-wiring.test.ts`). Several compose onto one base under `<base>--<d1>+<d2>`, domains sorted (`src/catalog/catalog-id.ts`); the renderer resolves such an id by parsing it (`catalogRecordFor`), never from a record per combination, and a reversed spelling is refused. A domain `selection.json` pins `domainId` and may append `notFor` edges to base entries (`appendNotFor`), never replace one; a mini-skill naming a domain type declares `domain:`; a domain's semantic checks declare the types they read (`requires`) and run only where the catalog holds them. Every type's layer (core, agentic, domain) is `src/catalog/layers.ts`, gated by `src/catalog/layers.test.ts`.
- Factory modules never import controls (ADR-0233). The default and a2ui-basic bodies carry `builtinControls` (`src/catalog/controls.ts`), which defines the controls a surface needs on demand, and persona entries inherit it through `composeControlLoaders`. A factory that mints another tag inside its control names it in `uses`, and a sub-element tag needs its family's descriptor to list it in `defines:` (generated into `registry.gen.ts`, which `controls.ts` folds into alias records; never hand-listed here); the gate is `src/renderer/builtin-controls.test.ts`.
- No catalog registers eagerly. The default `agent-ui` catalog, a2ui-basic (both ids) and every shipped `<base>--<persona>` pairing are lazy records in `src/catalog/records.ts` (ADR-0241 and its Amendment 1): an eager manifest plus a dynamic import of the body, loaded the first time a surface names the id. A renderer built after a body has loaded in the module registers it at once (the warm memo). A new shipped catalog or persona fragment needs a record there; `src/catalog/records.test.ts` holds the list and each manifest equal to the bodies, and `packages/agent-ui/app/src/catalog-lazy.bundle.test.ts` fails if a body (or `controls.ts`) is imported statically. A test that asserts synchronously after `ingest` warms first: a top-level `await createRenderer().preload('agent-ui')` after the imports (not a `beforeAll`, which runs after a renderer built at module or describe scope), or `await renderer.preload(id)` for another id.
- Catalog content is hand-curated, never generated (ADR-0173 cl.5). The agreement gate `src/catalog/default/descriptor-agreement.test.ts` checks each row against its component descriptor.
- Each catalog has a `selection.json` sidecar (per-type `intents` and `notFor`, ADR-0232) loaded by `src/agent/selection-guidance.ts` and rendered on the prompt inventory line. A new emittable type needs an entry or `src/catalog/selection-guidance.test.ts` fails; an edit moves the byte-pinned baseline, so recapture it deliberately. `npm run eval:agent-behavior` (`tools/agent-eval/`) derives one case per `notFor` edge from these sidecars through `selectionGuidanceFor`.
- Each fragment folder under `src/catalog/personas/` is pinned by its agent manifest in `site/lib/agent-manifest/` (ADR-0235). An edit to a fragment's `catalog.json` or `selection.json` reds `site/lib/agent-manifest/agent-manifest.test.ts` until the writer runs from the repo root: `AGENT_MANIFEST_WRITE=1 npx vitest run --project site site/lib/agent-manifest/agent-manifest.write.test.ts`. A new fragment folder needs a hand-written manifest first.
- The capability registry (ADR-0237) is a derived index over the catalogs, sidecars, personas, mini-skills, packs, corpus shards and the component descriptors, never a source. The pure model is `src/registry/` (`./registry` subpath, no `node:*`, no import from `src/agent/`); the Node loader and CLI are `tools/registry/`. `site/capability-registry.json` (and its `site/public/` twin) and `src/registry/selection-projection.gen.ts` are generated: after a descriptor, catalog, sidecar, persona, mini-skill, pack or corpus edit run `npm run generate:registry`, or `tools/registry/generate.test.ts` fails and names it. `selection-projection.gen.ts` is the sidecars alone as pure data, the browser-safe copy for in-page tooling: `selectionProjectionFor(catalogId)` on `./registry` resolves it with the same id rules as `selectionGuidanceForId`, and `src/registry/selection.test.ts` holds the two equal. The loader's persona list is hard-coded and held equal to `SHIPPED_PERSONA_CATALOG_MANIFESTS` by `src/registry/registry-wiring.test.ts`, so a new persona fragment updates both. The registry never moves a prompt byte, and a derived `<base>--<persona>` catalog inherits its base's mini-skills and exemplars: `selectMiniSkills` and `retrieve` match on the base segment of the catalog id (ADR-0243 cl.3, amending ADR-0172 SPEC-R6); both also follow the turn's selected domains (`selectedDomains`): `retrieve` drops another domain's composites, ranks the turn's own first and never pads with a zero-score record (T-0238, pinned per shipped preset by `src/corpus/retrieve-presets.test.ts`). `retrieve` also drops a record that commits a `/secret` key the turn's persona foundation does not name: `produce()` parses the paths in the `## Foundation` block into `hiddenState`, so one game's board never frames on another game's turn on a shared catalog (T-0315; `site/pages/agent-admin-presets.test.ts` pins every committed key to its own preset's foundation). A persona composite (CardTable, BookingForm) lives in its own exemplar shard `corpus/exemplar/v1_0/<base>--<persona>.jsonl`, admitted against the composed persona catalog and retrieved only on that persona's turn (T-0240); the live loaders read the base shard plus every persona shard through `tools/corpus/exemplar-shards.ts`, and the Worker imports each file (held equal by `tools/corpus/exemplar-shards.test.ts`). `a2ui-basic` has its own `basic-dialect` mini-skill (`catalogId: a2ui-basic`, T-0077), so a Basic turn, and a `a2ui-basic--<persona>` turn, selects it and never an `agent-ui` module.

## Boundaries

- Trust boundary: provider keys stay server-side behind the dev-proxy mount `/__a2ui/agent` (`tools/agent/dev-proxy-plugin.ts`, ADR-0073 clause 5). No key, provider adapter or `produce()` import may enter `@agent-ui/devtools` (ADR-0200). `scripts/e2e-admin` answers `/__a2ui/agent` from fixtures through Playwright routes and adds no key path (local only, no CI job).
- Node-only fence: no module under `src/agent/` imports `node:*`; its prompt, sidecar and dogfood assets come from the build-time embed (ADR-0236), gated by the NODE-FENCE leg of `src/agent/gates.test.ts`.

## Wire and validator spine

- Wire types `src/protocol.ts`; validator `src/renderer/validate.ts`.
- The validator judges structure only. A persona may declare `semanticChecks` on its `PersonaCatalogManifest` (contract `src/catalog/semantic-check.ts`, ADR-0238); `produce()` runs them after the validator and feeds a finding into the repair round, shipping tallied at the round bound. Both hosts resolve them for the selected catalog through `semanticChecksDeps` (`tools/agent/chat-validation.ts`). A check also reads the action a client turn answers (`SemanticCheckInput.action`, T-0172) and a say turn's typed words (`intent`, T-0232) and declared open target (`target`, T-0214), and an action turn or a targeted say turn whose round sends no payload is judged too, so a click answered in prose alone is repaired. The producer's own reply check (T-0234): a reply that names a session surface id or opens a correction of an earlier turn gets NARRATED_MECHANICS and one repair round, then ships tallied NARRATION_UNCORRECTED. The Croupier's hand, bet-controls, action, deck and rules checks are `src/catalog/personas/croupier/checks.ts`. The hidden game state checks (`src/catalog/hidden-state-checks.ts`, T-0230) ride every catalog: a word game or Battleship commits its answer at `/secret` in the surface data model, and every mark is judged against it. The composite-moment checks (T-0208, `src/catalog/composite-moments.ts`) are one data table of "use composite X for moment Y" rows; `semanticChecksDeps` appends them after the hidden-state checks and resolves each for every catalog that holds its composite (`requires`), so a plain `agent-ui` turn runs the games rows and `a2ui-basic` runs none. The framed-choice check (T-0258, `src/catalog/framed-choice-check.ts`) comes last on every catalog with Card and Button: two or more sibling Cards that each hold only one Button (directly or through a lone CardContent or CardFooter) get FRAMED_CHOICE and a repair to one Row of plain Buttons.
- SPEC `.claude/docs/spec/a2ui-runtime.spec.md`, `.claude/docs/spec/a2ui-message-lifecycle.spec.md`; LLD `.claude/docs/lld/a2ui-renderer.lld.md`, `.claude/docs/lld/a2ui-validator-finalize.lld.md`. The full set is `.claude/docs/spec/a2ui-*` and `.claude/docs/lld/a2ui-*`.

## Response type and turn bounds

- On an a2ui-enabled turn the model replies in prose and shows UI only by calling the terminal `render_surface` tool (ADR-0242, spec `.claude/docs/spec/response-type-selection.spec.md`). `src/agent/response-type.ts` owns the tool definition, the response vocabulary and `detectUserOverride`; `produce()` (`src/agent/produce.ts`) reads the captured tool input as the A2UI payload, and its required `reply` line as the note when the turn has no text (T-0194), and runs it through the same validate and repair chain, and `src/agent/providers/anthropic.ts` ends the round on that call without executing it. The reply text streams as `textDelta` meta-lines (`src/agent/meta-line.ts`); A2UI lines still arrive only after validation.
- The prompt side is `src/agent/prompts/grammar.md` (inside the byte-pinned baseline) plus `response-preference-{text,surface}.md` and `a2ui-off-note-line.md`, which are embedded assets composed outside the four baseline prompts: edit them, then run `node scripts/generate-agent-assets.mjs`. `npm run eval:agent-behavior -- live --leg response-type` (key needed, Kim's manual run) scores text vs surface vs both; its keyless `selftest` rides `check:scripts`.
- A turn is bounded as a whole: `src/agent/deadlines.ts` (`withTurnDeadline`, `TURN_DEADLINE_MS`, `TurnDeadlineError`, the `AgentTimeoutError` family) wraps the produce loop, and `providers/anthropic.ts` adds the first-byte and `StreamStallError` waits. Hosts write `failureMessageFor` (`tools/agent/chat-validation.ts`), never the raw error. The Anthropic request shape is the pure `buildRequestBody`, driven by the per-model capability table `src/agent/model-capabilities.ts` (T-0185, exported as `./agent/model-capabilities`): adaptive thinking with `display` (default `summarized`) plus `output_config.effort` on current families (Haiku 5.5 included, with its own `max_tokens` tiers and an explicit `low`), the legacy `budget_tokens` only for `haiku-4-5`; `modelSettings` (thinking mode, display, max tokens, cache TTL) is checked against the model's row and a rejected field is dropped before the call. No sampling param is ever sent. A new served model gets a row there (`src/live-agent/model-capabilities.test.ts` holds every implemented `providers.json` model to one).

## Test kit

- `tools/testkit/` holds the keyless A2UI test kit (T-0011): the scenario format, scripted transport, provider, MCP server and tools, the mount and interaction loop, the catalog-generated matrix, seeded defects under `tools/testkit/__seeded__/<layer>/` (pinned) and fuzz. Its vitest legs live in `src/testkit/`, because the browser shard only globs `src/**`.
- Commands: `npm run test:a2ui-kit`, `npm run test:a2ui-kit:browser`, and `node --experimental-strip-types packages/agent-ui/a2ui/tools/testkit/kit.ts selftest|run <file>|list`. The format, every finding code and the pin procedure: `tools/testkit/README.md`.
- A new catalog type gets a generated matrix cell with no hand file; it reds `src/testkit/matrix.test.ts` until it can be derived, validated and mounted.
